# gujitools 依赖（CLI + GUI 全量）
# 安装: pip install -r requirements.txt
#
# ⚠️ 只有这一份。CLI 与 GUI 现在打进同一个目录、共享同一份 _internal
# （见 build.py），构建环境本来就必须同时具备两边的依赖，拆两份文件只会
# 造成「两处事实来源」。
# 曾有两份（requirements.txt / requirements.gui.txt），而 build.py 因怕 pip
# 重解析把 CPU 版 torch 顶掉，只手写了「GUI 增量」清单、并不装
# requirements.gui.txt —— 结果往 gui 那份里加的依赖对打包毫无作用，
# `collect_submodules()` 对缺失的包静默返回空，PyInstaller 全程不报错，
# 只有运行到对应功能才炸（markdown 就因此让手册退化成原始文本）。
# 现在全量装这一份，build.py 只跑一次 pip install。

# ⚠️ PySide6 **必须带上限**：Qt 官方写明「Qt 6.12 是最后一个支持 Windows 10
# 的版本」，而 Qt 对 Win 的下限就是 Qt 版本说了算（当前 6.11 官方支持
# Win10 1809+ / Win11；Win7、8 从 Qt 6 起一律不支持）。放开上限后哪天重建
# 构建环境装到 6.13+，Win10 用户的支持就没了，而且不会有任何人报错。
# 另一个上限理由：6.11 的 Linux wheel 是 manylinux_2_34，对应 Ubuntu 22.04+；
# 若要支持 Ubuntu 20.04（glibc 2.31），需降到 6.8.x（manylinux_2_28）。
PySide6>=6.6.0,<6.13              # Qt 绑定
PySide6-Fluent-Widgets>=1.5.0     # import qfluentwidgets（GPLv3，商用另购授权）

# ---- 用户手册：docs/guide/*.md → HTML → 系统浏览器 ----
markdown>=3.4            # import markdown（纯 Python，无二进制依赖）
