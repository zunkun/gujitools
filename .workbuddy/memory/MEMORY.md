# gujitools 记忆

古籍重製 PDF→提图→检测框→去底色→生成PDF。双入口共用算法：`cli.py`(打包`guji`)/`desktop.py`(PySide6+qfluentwidgets)。分层`utils←core←{cli,functions,desktop}`**严格单向**。⚠`docs/**`基准 main，本分支**以代码为准**；过程见`2026-10-0*.md`。⚠本文件有上限，**新增先删旧的**。

## 提交纪律
⚠️长期大量未提交在制品。**AI 禁止自动 `git commit`**。提交前：①`git diff > /tmp/b.patch` **加**逐个`cp`未跟踪文件；②跑相关自测；③`git add -A` 后 `git diff --cached --name-only | grep -E "_out/|\.png$|\.log$"` 兜产物。⚠自测退出码 **127 是伪错误**（末段`QThread: Destroyed`）且**会吃掉收尾一批模块**⇒必须比对 `--list` 计划数 vs 日志`==标题==`数再用 `--only` 补跑。

## 关键契约
- ⚠⚠**「源 PDF」↔「提取图片」成对存在**。⚠️源 PDF 在图上是 **`startEvent`、没有 `stage`**（语义标记 `SUPPLY_TASK_SOURCE`）⇒**不能按 stage 认**；`ports.source_pdf_node_ids()` 走「事件类型**或**节点名」任一命中。配对唯一真源＝`ports.paired_node_for_stage(diagram, node_id)`（**双向**）——⚠️**别在编辑器里写死 `"extract"↔"startEvent"`**。⚠️**删除有两条路径，两条都要成对**：`ask_delete_selected()`（工具栏）与 `remove_selected()`（**键盘 Delete**）——凡"某动作要联动"**先 grep 有几条入口**。⚠️返回 `None` 时调用方**必须自己再判**对方是否真在图里。
- ⚠⚠**页头 PDF 图标：只在"流程压根不吃 PDF"时整颗藏起来**（判据 `ports.flow_needs_source_pdf()`，抽成 `manifest._flow_needs_source_pdf()` 供 `_missing_source` 复用、**别两处各判**）。⚠️**空壳任务**（还没选 PDF 但流程要 PDF）必须**恒显示**（文件被移走时它同样是补救入口）——要分清「流程不碰 PDF」（藏）与「还没选」（显）。构造期无 `task_id` 时给 `True`。自测＝`step_ports` 第 8 节＋`flow_ui` 第 18 节（⚠️后者**必须替掉 `QMessageBox.question`** 否则真弹模态＝看门狗 `os._exit(3)`）。
- ⚠⚠**「输入入口红框」与「缺输入才亮」是两套，会互相覆盖**。
  - 常驻红框＝**标识入口**（页头插图/插目录、预览区＋/📁）⇒ `ui/widgets.py::mark_input_entry(button)`（**两处用**故必须收敛成一份）。🗑 删除、流程、改名**不标红**。
  - 动态高亮＝**缺什么才亮、补上就灭**＝`manifest._set_tool_highlight`。⚠️ 它灭时 `setStyleSheet("")` **会把常驻红框一起抹掉**⇒ `_refresh_source_actions` 里先走动态、再**无条件重贴** `mark_input_entry(insert)`。⚠️别"优化"成只用一个。**同一按钮上只能选一套**。
  - ⚠️⚠️**自测判"有没有红框"不能看有没有 `border`**：qfluentwidgets ToolButton **自带** border 样式表，`'border' in styleSheet()` 对**所有按钮**为真（第一版探针全绿且毫无意义）。正确＝`str(theme.DANGER) in styleSheet()`。同理**别断言 `styleSheet()==""`** 判"高亮撤掉"——用**红字是否消失**（`source_warning.isHidden()`）判动态高亮。
- ⚠⚠**入口节点：没有上游也要有输入**（用户口径"某个节点作为第一个节点，一定要可以有输入可用"）。此前图片输入只有一条来路＝上游 `pages` 端口，自定义流程把「检测文本框」放第一位时**连坏三处**：①`stage_input` 回溯不到供给方→弹"输入未接好"；②页面清单只有 extract 成功才刷新→预览永远"暂无图片"；③插图只写 `stages/extract/`＋拿栈页号当格序用→插完列表不刷新。

## 硬规则
- ⚠⚠⚠**图必须压过静态连线表**（2026-10-06 掉头，用户**第二次**提同一个问题时的病根）。`ports.SUPPLIERS`＝**写死在代码里的默认流程连线**，只能兜底。原规则"先静态声明、后沿图回退"是**反的**：只要静态供给方还留在流程里，用户画的线一律作废。证明＝两条**节点集合相同、连线不同**的流程（默认 `extract→detect→rembg→print` vs 用户自己连的 `extract→print`）`print` 取图目录**完全一样**。⇒ **BPM 化只覆盖了"顺序"、没覆盖"语义"**。现在 `store.stage_supplier`：①**不声明的端口⇒没有这个输入**（`ports.stage_inputs` 唯一真源，**必须在查图之前**，否则 `print` 会沿图撞上 `detect` 拿到 `boxes.json`）②**图给出唯一答案⇒图说了算**（`FlowDiagram.producers_of`）③**图说不清⇒退回静态声明+条件开关**。⚠️③是**确定性要求**：默认流程带「是否拼版」网关，两条**实线**都进「PDF排版」，必须靠 `print_pages_supplier(imposition_active)` 这个运行态选，靠遍历顺序选是随机的。⚠️`producers_of` **遇到产出方就停**（线性链里 `print` 的产出方是 `rembg` 不是 `extract`）；按"可达"判会把线性链也误判成歧义＝图白做。自测＝`step_ports` 第9d节。
- ⚠⚠**改名不断绑**：阶段身份是节点的属性（落盘在 `guji:stage`，`load` 优先读它），名字只是显示标签。以前改名**重算**阶段＋`to_xml` 不写身份——「图片去底色」改成「AI 抠图」就接不回来了（"默认流程突然出现"的机制性原因：身份只活在名字里）。现在：认得出的名字换绑（改名切换步骤类型，有意保留），认不出的名字只改显示、保留原阶段；本来没阶段的不许凭空接上；解绑请删节点。`stage_unbound` 信号已删（引起它的事件不再可能发生，留着只会误导后人）。自测＝`flow_ui`（保留/换绑/不凭空接上/存盘重读带身份）。
- ⚠⚠**条件开关从 spec 派生**：`scheduler.CONDITIONS`＝`{步骤:步骤 for role=="optional"}`，开关状态走通用 `store.step_enabled`（`drafts/<步骤>.json` 的 `enabled`）＋`store.scheduler_flags` 一次建成。再加可选步骤，条件表、flags 键自动跟着走。⚠️唯一的调用方特例是 `imposition` 那一键用传入值覆盖——调用方传的是 `imposition_effective()`（在流程里＋`area==1`＋开关），纯开关读数在区域模式不支持时会把下游指去空目录。自测＝`step_ports` 第9e节。
- ⚠⚠**读不到流程给空，不伪造**：`runs.flow_stages` 异常曾回 `set(STAGES)`、`task_rows_worker._stage_chips` 曾就地编四个默认胶囊——流程图坏了的任务在列表里冒出四个默认阶段（"默认流程又出现了"的观感来源；合法空图也会触发）。现在两处都给空（键集合/行渲染不受影响）。自测＝`flow_bpm` chips⑤（monkeypatch 让 `task_slots` 抛错——删任务目录测不到，`task_diagram` 对缺失文件会回落默认模板）。
