## 修复：print 面板「标题切换」节点表高度不自适应

- 根因：`print_form.py` 写死 `_NODE_ROW_H=30` / `_NODE_HEADER_H=28` 算 setFixedHeight，而 qfluent 表格实际 `defaultSectionSize()` 为 38px、表头约 33px；1 行时表格 58px，viewport 仅 23px 却要装 38px 行 → 单元格控件被压扁/裁掉（离屏实测 viewportH 23/53/83/113 vs 行高 38）。
- 修复：新增 `_node_row_height()`（取 defaultSectionSize 与 cellWidget sizeHint 的较大值，下限 34），`_update_nodes_table_height()` 按 `表头 sizeHint + min(行数,4)×行高 + frameWidth×2` 计算，并同步 `setDefaultSectionSize`；空表改为直接调用自适应（原写死 40px，首行加入会跳变）。
- 验证：离屏测量 1~6 行 viewport ≥ 行数据像素（1 行 73px、4 行 187px、>4 行 scrollMax=76 可滚到最后一行）；`apply_args` 回填/清空路径高度正确；全量自测 102 项断言通过。

## 改造：详情页顶部步骤条（原 PushButton 标签堆 → 自绘 stepper）

- 原实现是 4 个 `PushButton` 拼文本「1. 提取图片 · 成功 84/84」，用样式表换底色，既像标签堆叠、也看不出先后顺序。
- 新 `step_bar.py`：`_StepBadge`（26px 圆形徽标，成功画 ✓，其余画编号）、`_Connector`（连接线 + 箭头，左侧步骤完成时变绿）、`_ElidedLabel`（宽度不足时省略号）、`StepItem`（徽标 + 标题 + 副标题，整块可点击、悬停底色）、`StepBar`（卡片底 + 均匀分布 4 步）。
- 关键实现选择：**全部自绘，不用样式表**。子树里只要出现 `setStyleSheet`，Qt 会把 QFrame 底色填白（实测：步骤条卡片底色 #f7f9fb 被白色块盖住），所以卡片底色/当前步骤胶囊都在 `paintEvent` 里画。
- 接口：`set_step_status(index, status, progress, completed)` 拼「状态 · done/total」；`set_steps/set_current/mark_completed/buttons/_completed` 兼容保留（自测断言依赖 `buttons` 与 `_completed`）。`StepBar(steps)` 里要 `list(steps)`——页面传的是生成器。
- 语义修正：`store/runs.stage_states` 新增 `completed`（该阶段历史上是否有过 success）。原步骤条"已完成"只增不减，与最新状态文案矛盾（失败重试后文字显示"失败"却仍标已完成）。现在徽标跟随 completed、副标题颜色跟随最近一次 status，「有产出但重试失败」= 绿对勾 + 红色副标题。
- 实测：窄到 700px 时 pill 收缩且文字省略号；`minimumSizeHint` 从 896px 降到 386px（原来会把整页最小宽度顶宽）；全量自测 102 项断言通过（含「步骤条已完成高亮」，未改测试）。
