# 2026-10-08

## 拆分后的类型检查期宿主面（pyright 837 → 0）

用户诉求：「这些拆分后的代码，修复 pylance 报错」。约束同前：**不许改运行期行为**。

### 根因

拆成 Mixin 后每个类都是独立类，pyright 解析 `self` 只看到自己那一小块：
兄弟 Mixin / 主类的成员看不到、**Qt 基类的成员也看不到**
（`super().mousePressEvent(...)` 会解析到 `object`），800 条
`reportAttributeAccessIssue` 由此而来。

### 做法：每子包一个 `_host.py`（类型检查期宿主协议）

```python
# canvas/_host.py —— 基类 = 主类去掉本地 Mixin 后剩下的基类
class CanvasHost(QGraphicsView):
    _image: Any
    def image_rect(self) -> QRectF: ...

# 各 Mixin
if TYPE_CHECKING:
    from ._host import CanvasHost
else:
    CanvasHost = object        # 运行期退化成 object ⇒ MRO / 行为零改动
class CageMixin(CanvasHost): ...
```

六个宿主：`CanvasHost` / `DialogHost` / `ImageViewHost` / `ImageViewerHost` /
`RembgViewerHost` / `PrintPreviewHost`。`_host.py` 只在类型检查期被导入。

### ⚠️ 四个坑（详见 `docs/dev/refactor-modularity.md` §10）

1. **`__init__` 绝不能进宿主面**：主类 `super().__init__(parent)` 会命中宿主的桩，
   `parent` 被当成 `placeholder`/`empty_hint` 报错（四个查看器同时中招）。
2. 只有**首字母大写**的名字才当类型（`max(...)`/`build_mesh(...)` 不是类型）。
3. 相对导入要解析成**绝对模块名**（`from .canvas import X` 在不同包里指不同模块）。
4. 属性别一律 `Any`：`self._fit_ratio = EDIT_FIT_RATIO` 要查常量表拿 `float`。

另：`TextBlockItem._canvas` 的注解从 `"EditorCanvas | None"` 改成
`"CanvasHost | None"`（`add_text_block` 里 `item._canvas = self`，拆分后 `self`
是 `TextMixin`）；`image_editor/__init__.py` 的 `__all__` 原先是**裸名字**（值不是
名字），已改成字符串字面量；`tools/gen_api_docs.py` 现在跳过单下划线开头的私有模块。

### 守卫与回归

- `tests/selftests/_context.py::check_type_only_host()`：宿主面**恰好**覆盖全部成员
  + 每个 Mixin 都是「TYPE_CHECKING 期继承、运行期 object」+ 运行期 MRO 里没有宿主类。
  双向验证：漏成员 → 红；去掉运行期兜底 → 红；还原 → 绿。
- **pyright 项目本体 0 error 0 warning**（400 文件）；pyflakes 零新增。
- AST 等价：六个子包 380 个方法逐个比对，唯一差异是上面那处 `_canvas` 注解。

## 扭曲笔刷：修复"拖越久越卡 + 松手崩溃"（用户报障）

### 根因（不是渲染慢，是**落点重采样把 carry 累加错**）

`image_editor/distortion.py::StrokeSampler.extend` 的记账写成
`self._carry += max(0.0, length - walked)`，而 `walked` **已经包含**"吃掉旧
carry"的那一截 ⇒ 旧 carry 被加回第二次，`_carry` 每段单调增长（实测
6.75 → 21.7 → 981 → 2136）。一旦 `carry > step`（step = 117×10% = 11.7），
`walked += step - carry` 变负、`ratio = min(1.0, walked/length)` 得到**负数**，
于是每段空转 `carry/step` 次、抛出成百个远在天边的假落点：

```
拖 30s/3750 事件：每段落点 中位 89、最大 184（散布 1000~2077 图像 px）
                  脏区 中位 161×412、最大 737×897 预览 px
                  每帧渲染 56 ms（最差 535 ms）、拖动墙钟 586 s
```

假落点不只慢，**结果也是错的**（位移被拉成上千像素）。

**修法**：改成"距段首多远落下一个点"的 `needed` 记账：
`needed = step - _carry; while needed <= length: emit(needed/length); needed += step;`
`_carry = length - (needed - step)`；`start()` 里把 `_carry` 归零。
修后每段 1~3 个落点（总 720 vs 35453）、`_carry` 恒 < step、脏区恒 ≈52×59。

### 第二处：预览按"整块 128 瓦片"渲染，多算 10 倍

脏区只有 ~52×59 px，却按覆盖到的 128×128 瓦片整块渲染 ⇒ 每帧 10.4 ms。
`render_tiles_into` → **`render_rect_into`**（只渲染精确脏矩形；全仓库只有一个
调用方）。`_accumulate` 的脏区半径加**场双线性取样的外扩** `2/scale`（原来只加
2 图像 px，边缘会留一圈没跟上的旧像素）。

### 第三处：单帧渲染量加预算

鼠标猛地一跳（或系统把一串 move 并成一个事件）脏区能横跨上千 px，一次渲染完
就是一次卡顿。`DISTORT_PREVIEW_RENDER_PIXELS = 60_000`：超预算的部分**按行走、
整段挂回** `_distort_preview_dirty_rect` 留给下一 tick（优先"离鼠标近"那段），
节流器保持 active 直到排干净。

### 量化（3000×4000 扫描件、笔刷 117、一笔 30 s）

| | 修前 | 修后 |
|---|---|---|
| 每帧（中位/最差） | 56 ms / 535 ms | **1.28 ms / 2.1 ms** |
| 拖动墙钟（3750 事件） | 586 s | **4.4 s** |
| 每段落点数 | 中位 89 | 中位 2 |
| 落点累加 | — | 0.28 ms/帧 |
| 松手提交（6.5 Mpx 大笔划，后台+可取消） | 66 s（30 s 拖动） | ~5–6 s，**与时长解耦**（400 事件 5.2 s vs 3750 事件 6.7 s） |

## 修复用户报障：① 适应窗口把图缩小 ② 预览弹窗里编辑没落到拼版页

### ① 「适应窗口」点了图缩成 1/4（**既有 bug**，非本轮布局改动引入）

`dialog_toolbar.py` 里写的是 `self.fit_btn.clicked.connect(self.canvas.fit)`，
而 `Qt` 的 `clicked` 会顺手塞一个 `checked: bool` 位置参数 ⇒ `fit(ratio=False)`
⇒ `float(False)==0.0` 被 `max(0.2, ...)` 夹成下限 0.2 = 缺省 0.8 的 1/4。
实测 1000×700 图在 1124×801 视口：点前 0.896 → **点后 0.224**。

⚠️ 同行的 `zoom_in/zoom_out` 没这个毛病——它们**没有参数**，PySide6 才不会多塞。
**判据：只要槽函数接受一个位置参数，`clicked` 就会喂 `checked`。**

两层修法（都要留）：
1. 接线套 lambda：`clicked.connect(lambda: self.canvas.fit())`；
2. `canvas/core.py::fit()` 里 `ratio` 收到 `bool`/非数时按 `None`（缺省）处理。

### ② 预览弹窗里编辑，画布/左列不跟新

走访查确认 **画布那条链是好的**（真控件 + 真信号 + JSON 往返 + 截图都验过），
漏的是这三处：

- **任务流程左列每页缩略图**：`_imposition_source_thumbs` 是**按代表图路径**
  存在内存里的字典，同一路径换了内容照旧贴回旧 QPixmap。生效链里压根没动它。
  ⇒ 新增 `ImpositionPagesMixin._drop_imposition_source_thumb()`，并在
  `_on_imposition_source_edited()` 里调用（删掉命中项 → 走既有的"缺的补渲"）。
- **路径比较用字符串直接 `==`**：doc 里存原样串，调用方给的是 `Path(...)`
  （Windows 上 `/` 翻成 `\`）。任务流程那条链不比较（直接走生效链），
  但**独立拼图页** `_on_zoom_image_saved` 拿 `str(item["file"]) == path_text`
  比较，落空就**整段 return 什么都不做** ⇒ 静默不刷新。
  ⇒ 新增 `services/imposition.py::same_path/page_has_file/pages_having_file`
  （`normpath+normcase+abspath`，空串恒不等），独立页改成先**无条件丢画布
  缓存**再认归属。
- **画布缓存 `invalidate_image` 只 pop 原样字符串** ⇒ 换成规范化匹配
  （键仍是原样，只是清理时扫一遍同形键），调用方传哪种斜杠/大小写都能命中。

⚠️ 三条都是"**静默失败**"型：不报错、只是不刷新。凡是"编辑后界面没变"，
先查"是不是有个比较/查找悄悄落空了"。
