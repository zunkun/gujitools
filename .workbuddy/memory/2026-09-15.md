`family` 参数）。这是「项目里一条长期失效的配置」，顺带修掉。

## 阶段面板下拉框高度被压缩（ComboBox 比输入框矮 6px）

### 现象与根因
去底色面板的「area 区域模式 / type 输出类型」下拉框比同列的 `border`/`offset`
明显矮一截。实测：`LineEdit` = 33px、`SpinBox` = 33px、**`ComboBox` = 27px**。
根因在 qfluentwidgets：`LineEdit.__init__` 里写死 `setFixedHeight(33)`
（`SpinBox`/`DoubleSpinBox`/`EditableComboBox` 都继承它），而
**`ComboBox` 继承的是 `QPushButton`**（`class ComboBox(QPushButton, ComboBoxBase)`），
没有这个约束，高度由 `QPushButton.sizeHint()` 决定，只有 27px。`PushButton` 同样 27px。

### 修法：统一的 `combo_box()` 工厂
- `desktop/ui/widgets.py`：新增常量 `CONTROL_HEIGHT = 33` 与工厂
  `combo_box(items=None, width=None)`——`setFixedHeight(CONTROL_HEIGHT)` +
  `setMinimumWidth(0)`（qfluent 下拉的 `minimumSizeHint` 偏大，窄面板会撑破边界；
  这条原先散落在 2 处各自写），`items` 支持纯字符串或 `(文案, 值)` 二元组（值入
  `itemData`）。`desktop/ui/__init__.py` 一并导出。
- 7 处调用点全部改走工厂：`extract_panel.ext`、`rembg_panel.area/type`、
  `print_form.paper_size` + `_make_combo()`、`print_nodes._make_side_combo()`、
  `view._make_history_combo()`。改完项目里只剩工厂内部一处裸 `ComboBox()`。
- `detect_panel`（本阶段无参数字段、只有一颗主按钮）的「检测本页」也
  `setFixedHeight(CONTROL_HEIGHT)`；qfluent 按钮默认同样只有 27px，和兄弟面板的
  33px 表单行放一起显得扁。
- 顺带清理 `print_form._apply_focus_policy()`：里面为拿 qfluent 的 ComboBox 类
  写了 `try/except ImportError` 的局部导入，现已把 `ComboBox` 提到模块顶层、
  直接 `isinstance(w, (QSpinBox, QComboBox, ComboBox))`。

### 自测新增 6 条断言（102 → 108）
`tests/gui_selftest.py` 新增「表单控件高度」小节：`CONTROL_HEIGHT` 必须等于
`LineEdit().height()`；四个阶段面板内所有下拉框等高；`history_combo` 等高；
detect 面板主按钮等高；节点行（侧别/页码/标题）等高。
**关键坑**：断言不能用裸 `ComboBox().height()` 当基准——没有 `setFixedHeight`
的控件在未 `show()` 时 `height()` 返回 **480**（默认窗口高）；`LineEdit` 因为构造里
就固定高度，不 show 也能取到 33。节点行断言用**独立探针** `NodeListWidget()`
而非真实面板，避免 `add_row()` 发出的 `changed` 信号污染后续「是否已改动」断言。

### 顺带修掉自测的一处偶发失败
跑自测时偶发 `[FAIL] 进度 6/6 {'done': 5, 'total': 6, 'status': 'success'}`。
原因：`wait_worker()` 只看 QProcess 状态，进程退出时最后一条 `finished` 事件
（才带 `done=6`）可能还排在事件队列里没被 GUI 读完。修法：读完状态前先循环
`processEvents()` 轮询到 `done == 6`（上限 60 次 × 50ms）。属测试侧竞态，非应用缺陷。

- 实测所有面板下拉框/按钮 = 33px；`gen_api_docs --check` 最新；`check_docs.py`
  24 个文件链接/表格正常。
- 截图 6 张已重新渲染并覆盖 `docs/gui/screenshots/`；文档更新

## 第三步去底色：area=1 时左侧缩略图条显示整页（应为半页）

用户反馈「第三步图片去底色，area = 1 的时候，此时左侧预览框显示图片不对，
应该是显示一半的内容，因为已经拆分了」。

### 根因：`effect` / `crop` 键名不一致
`_page_thumb_for()` 返回的 spec 只有一个有效键 **`effect`**
（`{"boxes": 按缩略图比例缩放, "area", "border", "dpi": 300*sx}`），
但 `rembg_viewer._load_page_thumbs()` 一直在读 `spec.get("crop")` —— **永远是 `None`**，
于是 `crops` 全空、`ImageListWorker` 退化成直接渲染整页缩略图：area=1 拆出来的
`-r`/`-l` 两条目缩略图显示的都是整页（右半大图本身是对的，错只在左侧缩略图条）。

### 修法
`desktop/components/viewers/rembg_viewer.py`：收集 `spec.get("effect")` 改传
`ImageListWorker(thumb_paths, edge=96, effects=effects)`（原 `crops=crops`）。
`ImageListWorker.run()` 里 `if effect and any(effect.get("boxes") or []):
outputs = compose_region_output(...)` 的区域合成逻辑本来就在（支持 area/border/dpi），
**只缺调用方把 `effect` 传进来**——所以这是一行参数名的修复。

### 自测新增 3 条断言（108 → 111）
1. area=1 时该页拆成 `-r`/`-l` 两条目；
2. `_page_thumb_for` 给的 `effect.boxes[0]` 坐标只覆盖所属半页
   （左边界≈缩略图宽度一半、右边界≈缩略图宽度，容差 2px）；
3. monkeypatch `ImageListWorker.__init__` 抓调用参数，确认 `crops is None`
   且 `effects` 非空、长度 = 条目数、每条含 `boxes`。

### 踩坑

  言（provider→viewer→worker 的键名与坐标），不依赖渲染内容。

## 去底色预览：切换按钮改成自绘分段开关

用户反馈「去底色 中间预览区域 显示 原图和去底色后图片切换按钮不好看」。

### 原实现的问题
`RembgPreviewWidget` 顶部是 `[去底色结果] [原图]` 两颗 `PushButton`，选中态靠一段
写死样式的 `_ACTIVE_STYLE`（`background-color:#0078d4`）。三个毛病：
1. 饱和蓝 `#0078d4` 与主题色 `ACCENT`（深青 `#0E7C8B`）打架；
2. 两颗按钮之间留缝、各自带边框，看着像两颗不相干的按钮而不是一组开关；
3. 用它自己的 `setStyleSheet` 改样式——正是项目里反复踩的那类坑。

### 方案选择（先渲染对比再定）
用离屏探针把三种方案画出来对比：qfluentwidgets 原生 `SegmentedWidget`、
自绘胶囊分段、以及禁用态。最终选 **自绘胶囊分段**：
- 不用原生 `SegmentedWidget`：它是给页面导航设计的（底部指示条样式），
  而且**无法单独禁用某一项**——而这里需要「还没有去底色结果时禁用结果项」；
- 自绘能完全走 `theme` 令牌，和预览区浅色画布同层次。

### 改动
- `desktop/ui/widgets.py`：新增 `SegmentedToggle(QWidget)`（自绘 + `Signal`）：
  - 轨道 = `SURFACE_SOFT` 胶囊 + `BORDER` 描边；选中项盖一枚白底滑块
    （`SURFACE` + `BORDER` 描边 + 一层极浅投影）；
  - 段宽 = 文案宽 + 36，下限 80；高度常量 `HEIGHT = 30`（比表单控件矮，
    它不在表单里），`setFixedHeight` 后 offscreen 未 show 也能取到真实高度；
  - 接口：`current()` / `set_current()`（**不发信号**，防回流递归）/
    `set_item_enabled()` / `is_item_enabled()`，用户点击才发 `current_changed(str)`；
  - 悬停只对「可用且未选中」项高亮，`leaveEvent` 清掉；禁用项文案
    `INK_DISABLED`、不可悬停不可点击。
- `desktop/ui/__init__.py` 一并导出。
- `desktop/components/viewers/rembg_viewer.py`：删掉 `_ACTIVE_STYLE` 与
  `PushButton` 导入，`[去底色结果] [原图]` 换成一枚 `SegmentedToggle`；
  `_set_mode` 只做「`_mode` 变了才重载」；`_sync_toggle` 改成
  「`set_item_enabled("result", has_result)` + `set_current(按偏好回落)`」。
- **关键：`_sync_toggle` 不改写 `self._mode`**。老实现里 `active` 只是显示态，
  `_mode` 保持用户偏好（默认 "result"）；如果无结果时把 `_mode` 也改成
  "original"，结果一生成就会停在原图上，丢掉「默认看去底色结果」的行为。
  自测专门有一条断言锁这个。

### 自测新增 9 条断言（111 → 120）
分段开关替代按钮、固定高 30、有结果时结果项可用且默认选中、无结果时禁用并回落

## 分段开关补对比度（用户：「改成了胶囊，要有对比度（去底色效果，原图）」）

第一版把选中态做成「近白轨道 + 白滑块 + 深色文字」——太淡了，`SURFACE_SOFT`

离屏渲染四版并排：①近白轨道（现状）②灰轨道 + 白滑块 + 深色粗体文字
③灰轨道 + 白滑块 + **主色**粗体文字 ④主色实底滑块 + 白字。选定 **③**：
图②③都能一眼看出选中，③ 多一层色相线索且不至于像 ④ 那样变成一块实心色块
（第一版就是因为实心块与主题色打架才改掉的）。

  容器槽」，专门给需要衬出白滑块的轨道用。

### 问答：workset 与 stages/extract 为何两份相同图片
- 核实：**不是复制，是硬链接**。真实任务 0001 的 extract 84 张全部 `st_nlink=2`，`GetCompressedFileSizeW` 去重后本目录独占 0.0 MB（逻辑 119.4 MB）；0002 未跑过 detect，extract 独占 87.1 MB、workset 为空 → 磁盘上没有两份。
- workset 存在的理由是「顺序物化」而非存图：print 阶段把列表顺序写成 0001.png…，让 CLI 的 pdf_custom_sort_key 输出顺序与 GUI 列表严格一致（列表可插入/删除/重排）；另外它是执行期的可重建临时快照，与 extract 解耦。
- **但当前实现确实冗余，可直接复用 extract 当输入**：detect 只 `emit` 坐标（不读像素）、rembg 逐图独立（不依赖顺序与命名）、extract 执行时不碰 workset（run_extract_stage 直接渲染 PDF）。且 boxes/sizes 的 image_key 是 **stem**，链接后名字与 extract 一致 ⇒ 数据零冲突。实测 workset 与 extract 都是空间名（1.jpg），硬链接没被当作解决重名的理由。
- 可省的只有两个目录项本身（几十字节，非大文件）；剩两处真用途：②print 的顺序重命名（可改传有序文件列表）、③作为「extract 之后被外部改动」的隔离快照。
