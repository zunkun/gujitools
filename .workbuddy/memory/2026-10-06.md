## 创建任务页 6 条反馈（用户一次性提的，同日）

用户对着创建任务页截图提了 6 条：**①**任务名输入框不好看/ 高度不够 / 长度占满
整个屏幕太长；**②**PDF 输入不是必须的；**③**创建任务按钮不必等上传 pdf 才能点；
**④**任务名称可以有默认的「任务#0003」（0003 = 任务成功的序号）；**⑤**没填写
可以用上传的 pdf 名称；**⑥**创建任务成功但程序 GUI 不可见了。

### 根因与改法

- **①外观**：`pages/createtask/page.py` 原来用**裸 `QLineEdit`**（Win 上 21px 高
  的原生框、灰边）且 `addWidget(edit, 1)` 撑满整行 ⇒ 改 qfluentwidgets 的
  `LineEdit`（自带 33px = `ui/widgets.py::CONTROL_HEIGHT`）+ `setMaximumWidth(360)`
  + 行尾 `addStretch()`。
- **②③PDF 非必需**：`CreateTaskPanel.can_submit()` 从"必须有 PDF"改成**恒 True**；
  `CreateTaskPage._on_submit` 允许 path 为空串；`TaskListPage.start_create` 见空
  path 就**跳过整条指纹/查重链**直接建任务（没文件无从算指纹），且
  `_create_imported_task` 里**不排队** `SourceThumbnailsWorker`（否则拿不存在的
  文件去渲，会报错并卡住串行队列）。
- **④默认名**：`store.default_task_name()`＝`任务#{_next_task_no()}`，只作
  placeholder/提示。⚠️**落库时用实际 `task_id` 现算**（`create_task` 内
  `f"任务#{task_id}"`）——占号是 `mkdir(exist_ok=False)` 原子的、可能顺延，用
  预测值会让「任务#0008」落在 0009 号任务上。
- **⑤两级回落**：`rename_task` 空名 ⇒ 先 `source_path` 的 stem，再 `任务#号`。
- **⑥GUI 消失（真事故）**：`CreateTaskPanel.submit()` 里有一句
  `self.window().close()`——面板被内嵌进创建任务页后，`self.window()` 返回的是
  **主窗口**，点一次「创建任务」把整个程序关掉。已删；现与 `reject()` 同纪律：
  **面板只发信号，关窗/切页由宿主决定**。

### ⚠️⚠️ `Path("")` 是 `"."`（当前目录）——本轮踩的真坑

空源路径如果直接 `Path(task["source_path"])`，`exists()` 会**为真**（当前目录当然
存在），于是空壳任务被当成"文件在"，后面 `set_pdf` 去渲染一个目录、`extract`
拿它当输入，静默走到崩。详情页现在把三态分清（`set_task` 里）：

- `source_path is None` = **还没选**（空壳任务）⇒ 页头「尚未选择 PDF」+ 补选
  按钮，**不弹错误框**（"还没选"不是错误）；runner/submit 的 `not self.source_path`
  守卫拦住执行，提示改说"点页头的「选择 PDF」"。
- 路径在但文件不在 = **文件丢了** ⇒ 红色错误框（原有行为）。
- 正常。

`store.create_task` 里也显式挡了 `str(source_path).strip() in ("", ".")`，
索引里存**空串**而不是 `"."`。

### 新增：详情页页头「选择 PDF」补选入口

`manifest.py::PageListMixin._on_pick_source` + `_refresh_source_actions`；
`store.set_task_source(tid, path)`（**先复制进任务目录再改索引**——只改索引不

stages/ + thumbnails/{detect,print,imposition,source}/ + drafts/，但**保留

⚠⚠**清产物必须连"待写标记"一起清**（我第一版漏了，自测补钉）：`set_task` 开头

## 提示层「第一次进入不弹」（用户 2026-10-06 报障，已修）
**根因**：`shell.open_detail` 是**先 `page.set_task()`、后 `setCurrentWidget()`**，

⚠⚠**自测为什么一直抓不到**：所有相关用例都是 `probe.show()` **之后**才

## 插图支持选目录（用户追问"是否可以选择目录"）

> 现在提示选择的是图片，是否可以选择目录，比如去底色在第一个节点的时候，是否也可以输入目录

### ⚠️⚠️ 关键事实：`getOpenFileNames` **选不了目录**
原生 Windows 文件对话框只接受**文件**。所以"把整个扫描结果文件夹丢进来"
（一个任务一两百页图，逐张多选不现实）**必须有一个独立的目录入口**——
指望在文件对话框里选中文件夹是不成立的。这也是为什么不能只把
`getOpenFileNames` 的 filter 改成"图片与文件夹"（看起来像支持了，实际没有）。

### 实现
- `ImageViewerWidget` 新增信号 `insert_folder_requested`＋**第三个按钮**
  （📁 `ToolButton(FIF.FOLDER)`，tooltip「把一个文件夹里的图片批量插入」）。
  ⚠️ 按钮只在 `editable=True` 时建（与＋/🗑 同排）。
- `manifest.insert_pages_from_folder()`＝`getExistingDirectory` →
  `_insert_paths([dir])`；`insert_pages()`（＋按钮，多选文件）→
  `_insert_paths(paths)`。**两个入口共用 `_insert_paths` 一个实现**。
- ⚠️ 目录展开**复用 `StepSpec.collect_files`**（顶层→下钻一层→去重按名
  排序），**不另写一份遍历**——它在独立模块页已验证过。实测：4 个阶段
  `accepts_dir` 都 True、3 张图展开正确、`说明.txt` 被忽略、下钻一层 OK、
  **多个子目录各装图时返回空**（不乱拼不同书的页）。
- spec 取**当前阶段**的（`ports.spec_for_stage(self.current_stage())`），
  于是去底色/检测/生成PDF 打头都用自己的后缀口径。⚠️ `ports` 在
  `_insert_paths` 里**延迟导入**（会拖进 scheduler/bpmn_diagram 一整串）。

### 顺带修掉两个真bug（实测发现的）
1. ⚠️ **选输入目录本身会产生 `xxx-1.jpg` 重复副本**：`while target.exists()`
   的重名避让对"源==目标目录里的文件"也生效。修法＝复制前先判
   `source.resolve().parent == target_dir.resolve()`，命中的**跳过复制**、
   直接进清单（路径比较要用 `resolve()`，Windows 上大小写/短路径会不等）。
2. ⚠️ **清单里同一张图出现两次**：上面那条"已在目录里"的路径**没去重**。
   修法＝`_append_pages_to_manifest` 按 `str(file)` 去重，并**返回实际新增
   条数**（0 = 全都已在清单里，调用方据此提示、不刷新）。

### ⚠️ 一个我一开始误判的地方
复验时看到"重选同一目录产生 -1 重复"，我以为是 bug，细查发现**那是对的**：
源在**外部** `扫描结果/` 时本来就该复制一份进任务目录（任务要自包含）。
真正要防的是"用户选了**输入目录本身**"——所以自测钉的是后者。
⚠️别把"外部同内容再导入一次"当 bug 修，那会破坏"产物在任务目录里"的前提。

### 自测
