## 统一变换（GIMP Unified Transform）：修掉两处"半成品"，并补上滚动参数区

用户诉求：「按我发的图片（GIMP 的统一变换 / 工具分组 / 扭曲变换面板）实现变换功能
——我们自己的只能放大缩小、压缩、旋转，而且是对称的」。**只开发功能，不写测试**
（用户明示：变换相关的旧测试不用管）。

上一轮（10-08）已经把 GIMP 那套手柄与选项铺出来了（角方框=双轴缩放、角内小菱形=
透视、边中方框=单轴缩放、边上菱形=切变；方向/插值/剪裁/参考线/限制/从轴心/轴心/
调整范围/翻转），本轮做的是**把它变成真的能用**——查出并修掉三处问题。

### ① 烘焙的 QPainter 兜底路径会漂移（真 bug）

`bake_transform` 原来有一条路径：`interpolation="smooth"`（旧缺省）时直接
`painter.setTransform(xf)` + `painter.drawImage(rect, region)`。最小实验
（`probe_drawimage_semantics.py`，新建后已删）实测：

```
平移(−40,0)  source 模式 → 黑块 x=210（期望 220，偏 −10）
旋转90°      source 模式 → 黑块 (30,250)（期望 (40,260)，偏 −10）
切变(0,0.5)  source 模式 → 高 30（期望 20）
```

根因：`QPainter.drawImage(rect, image)` 在带变换的 painter 下**不等价于 `map(rect)`**
（平移量被加回去、旋转绕错原点），而且它只支持仿射、投影会被 Qt 近似。
⇒ **删掉整条路径**：新增 `geometry.warp_placement()`（唯一像素入口，走
`warp_region` 的逐像素反向重采样；只有"取不到 numpy"才退回 QPainter），
`bake_transform` 变成 `compose_transform` 的旧名别名。

### ② 预览与烘焙不是同一条数学

新增 `geometry.compose_transform(image, rect, xf, region, grow, interpolation)`——
**预览与烘焙共用的唯一实现**（画布 `_ensure_transform_preview` 直接调它算底图）。
量化验证（`probe_transform_consistency.py`：把画布现在显示的样子渲染成 QImage，
与真烘焙结果逐像素比）：

| 场景 | 修前 | 修后 |
| --- | --- | --- |
| 平移 −40 / 正向 | 内容**根本没动**（x=150，应 110） | 均差 **0.00** |
| 旋转 30° / clip / aspect / nohalo·linear·cubic·nearest | — | 均差 **2.1~4.3**（纯抗锯齿）|

### ③「方向 = 校正（向后）」的预览骗人

原来只有**烘焙**时取逆矩阵，预览仍画正向 ⇒ 看到的内容落点不是最终落点。
现在画布持有 `_xf_preview_direction` / `_xf_base_origin`：
`_preview_xf()` 在向后档返回逆矩阵，底图**连结果一起画好**（`compose_transform`
的 grow 形态）、浮层按预览帧矩阵摆放。方向切换时 `_sync_float` 整块重建底图。
向后档的均差 3.99（抗锯齿），截图人工核对一致（`06-backward-preview` vs
`07-backward-baked`）。

### ④ 右侧参数面板把下拉压成"一条线"（用户截图里"参数是坏的"就是它）

变换页有二十来个控件，实测**内容 876px / 可视区 483px**。参数区原来直接挂在
列布局里 ⇒ Qt 把整页压到最小高度：三个下拉（方向/插值/剪裁）被压成一条细线、
提示文字整段消失。
⇒ 按仓库既有做法（`panels/base.py::_scroll`、`panels/print_form.py`）加
`ScrollArea`：标题与「编辑历史」固定，只有参数区滚动；滚动条范围 0~377，
滚动到底能看到「限制」5 项 /「从轴心」3 项 /「轴心」/「调整范围」/「翻转」。

## 用户报障两条：① 页面卡顿 ② 操作节点规格（同日追加）

### ① 卡顿 = 整幅烘焙在主线程同步跑（实测 11.3 秒）

性能探针（12 MP / 3000×4000 扫描件）实测：

| 操作 | 耗时 |
| --- | --- |
| 切变换工具 | 26 ms |
| 建预览（首次抓取） | 52 ms |
| **拖动单帧** | **4.8 ms**（不卡） |
| **松手提交（整幅烘焙）** | **11 283 ms** ← 就是它 |

修法照仓库既有做法（`DistortionMixin._render_distortion_field`）：
`DISTORT_SYNC_RENDER_PIXELS` 预算内同步、超出走 `bake.run_with_progress`
（后台线程 + 进度框 + 可取消）。要点：

- `warp_region` 加 `progress` 回调，**逐块检查取消**（取消返回 `None`，
  绝不交付半张图）；`warp_placement` 用显式 `cancelled` 标记区分
  "用户取消"与"取不到 numpy"——前者不能退回 QPainter 硬画。
- 撤销点**先压、两条路只压一次**（曾经把 `_push_undo` 放进 `_bake` 里，
  同步分支就漏压了 ⇒ 用户改完图撤销不回去）；取消/失败走 `_undo_now()`
  退回并 `canvas.reset_transform()`。
- ⚠️ `compose_transform` 的返回值**多形态**（`grow=False` 返 QImage、
  `grow=True` 返 `(图, 原点)`）：`_transform_job` 里写成 `image, _ = ...`
  会在 clip 档炸出难懂的 `'QImage' object is not iterable`（QImage 可迭代）。
  必须 `result[0] if grow else result`。
- 剩余同步耗时：`_image_has_alpha`(12MP) 49 ms、建预览 52 ms——都在无感区间，
  没再动。

### ② 节点规格（用户 2026-10-09 明确口径）

**一张图共 16 个节点**：4 个四角**大方框**（双轴缩放，各内嵌 1 个**透视小菱形**）
＋ 4 个四边中点**中方框**（单轴缩放）＋ **4 个切变菱形**（每边 1 个）。

改动（原来是每边 2 个切变菱形，共 8 个）：

- `consts.SHEAR_AT` 从 `(0.25, 0.75)` 改成**标量 `0.75`**，`SHEAR_HANDLES`
  改成 `s_t/s_r/s_b/s_l`；新增 `SHEAR_FROM_CORNER`。
- **顺时针口径**（用户原话"都在 ¾ 处…靠近四边顶点的顺时针方向"）：
  边的参数化起点取 `t→tl / r→tr / b→br / l→bl` ⇒ 上边菱形偏**右**、右边偏**下**、
  下边偏**左**、左边偏**上**——绕一圈正好顺时针。
- **命中优先级**（`_hit_transform`）：轴心 → 透视小菱形 → 角方框 → 边中方框 →
  **切变菱形** → 整条边命中带 → 框内 → 框外。⚠️ 切变菱形**必须**排在边带之前
  （菱形就落在 8px 带内，顺序反了切变永远点不着）。
- **节点高亮/激活**：新增 `_focus_handle` + `_sync_focus_ring`（套在激活节点外的
  高亮环，`overlay._focus_ring`，cosmetic 2px、z=16）。悬停与按下**共用**这一套
  状态（`_set_handle_focus`），所以"点哪个节点哪个节点亮"。
  ⚠️ 统一变换下悬停**不写** `_hover_handle`（那是裁剪/收边的整边线高亮）。
- **切变跟手修正**（原来会跳）：系数 = 光标沿边位移 ÷ **该边自身方向的跨度**
  （左/右边是水平切变 ⇒ 除**宽度**；上/下边除**高度**），且 `mode` 里存的起点
  必须是**选区局部坐标**（过一次 `inverse`）——否则拖动时把矩阵平移量一起算进去，
  实测抓 ¾ 处菱形拖 60px、被抓的边跑 560px。验证：抓右边拖 60 ⇒ 右缘位移 60.3、
  左缘位移 0.00。
- `_shear_anchor()` 抽出来（对边整条不动），与"被抓的边不离开原边线"同一条。

### 验证（探针，收工已删）

16 个节点逐个"按在自己中心"的命中判定全部 == 自己；12 类节点按下 → 模式分别是
`xf_scale`(角) / `xf_scale1`(边中) / `xf_shear` / `xf_persp`，且 `_focus_handle`
就是被按的那个；框内仍是移动、框外仍是旋转（节点没把整块吃掉）。
回归 **704 项断言全绿**（含 imposition / module_edit_sync）。

## 用户第二批报障（6 条，同日追加）

原话六条：菱形大一些 / 四角嵌套菱形太小选不中 / 透视只动一个角其余不动 /
不停旋转越转越小 / 原始轮廓方正虚线不随变换动 + 背景格子 / 图片半透明。

### ① 两个菱形放大

`SHEAR_VIEW_PX` 11 → **16**（命中半径单独给 `SHEAR_HIT_VIEW_PX = 10`，不再蹭
通用半径）；`PERSP_VIEW_PX` 7 → **11**、`PERSP_HIT_VIEW_PX` 4.5 → **7.5**。
⚠️ **`PERSP_HIT_VIEW_PX` 必须 < `PERSP_INSET_VIEW_PX`(8)**：正按角点时才仍判成
"双轴缩放"，否则角缩放永远点不着（探针钉了这条）。

### ② 透视"动一个角、其余三个不动" —— 本来就对，补了验证

`transform_perspective` 一直是 `quad_to_quad(当前quad, 只改一角的quad)`。
探针实测拖 br 130px：tl/tr/bl 位移 **0.000px**。

### ③ 越转越小 = **两个独立原因，都修了**

1. **轴心每次提交都被重置到新画布中心**：`set_image` 无条件
   `_xf_pivot = self._rect.center()`。绕"每次都不一样的点"转 ⇒ 内容越扫越远、
   画布越撑越大。改为画布持有 `_xf_pivot_saved`（用户摆过的轴心，图片坐标），
   提交/换工具/换图都沿用；只有「重置」清空。
2. **`fit()` 会把 `_user_zoomed` 闸门清掉**：于是每次 `_set_tool`
   （它调 `set_fit_ratio` → `fit`）都重新 fit 一遍 ⇒ 倍率在 0.996/1.114 之间跳
   （探针用 `traceback` 抓到调用栈：`_set_tool` → `set_fit_ratio` → `fit`）。
   删掉 `fit()` 里那行；闸门只由用户缩放（`set_zoom`/`fit_selection`）置位。

修后：连转 6 次尺寸恒在 `(560,400) ↔ (400,560)` 之间（**不再增长**），
用户手动缩放过之后倍率恒 1.245（不再逐次缩小）。

### ④ 原图轮廓固定虚线 + 棋盘格背景

- **不新建图元**，直接复用 `set_image` 建的 `_border`：`_border_pen()` 在变换
  工具下给 cosmetic 1.5px `DashLine`（其它工具细实线）；`set_tool` 调
  `_apply_border_pen()`。它就是"这张纸的原始边界"，不跟变换走。
- 棋盘格：新增 `consts.CHECKER_{STEP,LIGHT,DARK}` + `EditorCanvas.paintEvent`
  先铺格再 `super().paintEvent`。
  ⚠️ **必须同时把 `setBackgroundBrush` 改成 `NoBrush`**：
  `QGraphicsScene.drawBackground` 会把视口整个刷成那个颜色，把棋盘格整块盖掉
  （实测：设了只剩纯色，改成 NoBrush 后两色格立刻出现）。

### ⑤ 变换内容半透明（见下面的"预览重构"）

浮层 = **白色方块（贴着变换后的四边形）+ 重采样内容**，整体按「图像不透明度」
半透明 ⇒ 原图轮廓与变换后的样子能同时看见。

### ⑥ 预览重构带来的性能坑（踩了两个，都修了）

用户口径要"内容半透明压在原图上"，于是浮层要带白底——原来是"底图填白 + 浮层
只有内容"。重构中踩了两个大坑，都是**每帧 1.8 秒**级别的：

1. **矩阵没跟着降采样**：`warp_placement` 用未缩放的矩阵算目标外框 ⇒ 12MP 图
   每帧重采样整幅 3000×4000（**1756 ms/帧**）。改成
   `QTransform().scale(k,k) * 预览矩阵`，目标就只有预览那一小块。
2. **`nohalo` 在缩小档要叠 9 趟采样**：0.33MP 目标仍要 **838 ms/帧**。
   新增 `consts.TRANSFORM_PREVIEW_PIXELS = 500_000`（预览预算，与扭曲的 2MP
   分开）+ `_xf_dragging`：**拖动中用 `linear`**，松手时
   `finish_transform_drag()` 把 `_xf_preview_keyframe` 置 None 强制按用户选的
   插值再出一帧（52 ms，用户看不到）。

修后 12 MP 实测：建预览 109 ms / **拖动 20.7 ms 帧** / 松手升质量 52 ms /
改不透明度 0.3 ms（不重采样）。

`image_editor` 系 + 邻近 10 模块 **791 项断言全绿**；`gen_api_docs` 重生成、
`--check` 与 `check_docs` ✅；pyflakes 无新增。探针与 `_scratch/` 已删净。

## 用户第三条报障：「不能实时预览，最后才预览」（同日追加，**交互模型改了**）

原话：「图片仍然不能实时预览，而是最后才预览，整幅重新采样，而且预览慢，
比如我只做了旋转图片，就需要等待很久，如果只是旋转，则可以实时渲染啊」。

### 根因：不是性能，是**交互设计错了**

上一轮把"松手即应用"当成特性保留，于是**每次松手都把整幅重采样一遍**
（12 MP ≈ 11 秒）——用户当然只能"最后才看到结果"。GIMP 的口径是
**松手保持预览、离开工具才应用**。

### 改法

- **松手只挂起**：`mouseReleaseEvent` 不再发 `transform_committed`，改调
  `make_transform_pending()`（只置 `_xf_pending`）。内容继续由画布浮层实时
  显示——旋转/缩放/移动都是**便宜的画布变换**，转多少圈都不用等。
- **离开工具/点「完成」才烘焙**：`_commit_transform(force=…)`。
  `_set_tool` 与 `_flip_transform` 传 `force=True`；松手路径不传，
  发现 `has_pending_transform()` 就直接返回。
- **大选区例外**：`make_transform_pending` 里 `_realtime_budget()` 判断预览
  选区是否超过 `TRANSFORM_PREVIEW_PIXELS`，超了就**退回松手即烘焙**
  （拖不动的"假实时"没意义）。
- ⚠️ 旧自测里"松手即应用"那几条断言描述的是旧交互，已按新交互更新
  （现在是"松手只挂起：像素与撤销栈都没动"＋"切走工具才烘焙"）。

### 顺带修掉的两个预览性能坑（都让"实时"名不副实）

1. **底图每帧整幅重画**（66 ms/帧）：`_backdrop_rect` 是"帧 ∪ 内容外框"，
   旋转时它逐帧变大 ⇒ 每帧判定"盖不住了" ⇒ 每帧重铺整幅。
   ⚠️ **选区 = 整幅时根本没有残余要画**（纸跟着内容走）⇒
   `_backdrop_is_whole()` 直接让底图 = 原图本身、位置 (0,0)、**永不重铺**；
   局部选区才用缓存的「纸」`_xf_frame`（原图 + 选区擦白，只算一次）。
2. **判据用错矩阵**：`_xf_preview_keyframe` 原来存 `self._xf`，于是**纯旋转/
   平移**也被判定"要重算像素"。改成 `_preview_warp_xf()`（= 缩放 ∘ 预览矩阵，
   **不含摆位**）⇒ 转动/挪动完全不重采样，只有缩放/切变/透视才重算。
   另：浮层底色从写死 `#ffffff` 改成**选区底色的代表值**
   `_region_backdrop_color()`（最亮采样与中心像素的均值），旋转后边缘不再有
   一圈白描边。

### 量化（12 MP / 3000×4000）

| | 修前 | 修后 |
| --- | --- | --- |
| 拖动单帧 | 拖动时每帧都在重铺底图 | **22.8 ms**（24/24 帧预览都在变） |
| 松手 | **11.3 秒**（整幅烘焙） | **60.9 ms**（只挂起，像素/撤销栈都不动） |
| 挂起后继续旋转 | — | 最慢 **198.9 ms** |
| 离开工具烘焙 | — | 11.4 秒（**只此一次**，有进度条、可取消） |

### 一致性复核

`preview == bake`：把画布显示（底图 + 半透明浮层）与真烘焙结果渲到同一坐标系
逐像素比，**平均色差 4.07**（抗锯齿级别；差分图里只有页边一圈抗锯齿与线段细纹）。
⚠️ 比的时候必须**同尺度**（预览会按 `TRANSFORM_PREVIEW_PIXELS` 降采样）且用
**默认 100% 不透明度**——半透明是"故意淡"，那时本来就该和全强度结果不同。

## 续：拖动中改走"图元原生仿射"（用户报"只旋转不能实时渲染"）

### 定位

上一轮把"松手挂起"做完了，但**拖动中每一帧仍在逐像素重采样**。实测（离屏，
`_scratch/xf_perf.py` + cProfile）：

| 场景 | 每帧 |
| --- | --- |
| 12 MP 整幅旋转（`linear`，拖动档） | **158–170 ms** |
| 同图 `nohalo`（精确档） | **442 ms** |
| 600×800（k=1，预览不降采样） | **158 ms** |

cProfile 的 96% 落在 `warp_region`：`_WARP_CHUNK_PIXELS=400_000` 把 950k 像素的
输出切成 3 块，每块一次 `_gather`（28 ms）× 3 + `sx/sy/den/valid` 的一堆临时数组
（70 ms）。⚠️ **关键认知：预览预算 `TRANSFORM_PREVIEW_PIXELS` 是"源像素"，
旋转会按 1.4×/轴 把输出撑大 ⇒ 输出恒约 1 MP ⇒ 不管原图多大都 ~180 ms/帧**
（所以 600×800 和 12 MP 一样慢）。

### 改法：两档，口径故意不同

| | 拖动中（`_xf_dragging`） | 首次 / 松手后 |
| --- | --- | --- |
| 像素 | **不重采样**＝`_xf_preview_region` 原图 | `warp_placement(_xf_preview_region, _preview_placement_xf(), _xf_interpolation)` |
| 图元矩阵 | `_float_fast_xf()` = `_placed_xf() * scale(1/k)`（**含旋转/切变/透视**） | `_float_placement()` = `scale(1/k) * translate(origin)`（**纯摆位，m12/m21 恒 0**） |
| 裁剪 | `_float_fast_plane()` 用 `QPainterPath` 掩膜（+0.5–1 ms） | `_cut_plane()` 四块补集 |
| 实测 | **0.6–2.2 ms/帧**（12 MP）/ 真实鼠标链路 1.8–11.5 ms | 400–500 ms（**一帧**，松手时） |

- **摆位矩阵只留一处定义**：新增 `_placed_xf()` = `translate(选区左上角) * _preview_xf(_xf)`，
  `_base_target_rect` / `_preview_placement_xf` / `_float_fast_xf` 全从它派生。
- ⚠️ **两档的图元矩阵绝不可混用**：快档是"像素是原图 ⇒ 图元带变换"，精确档是
  "像素烘过了 ⇒ 图元只能缩放平移"。混用＝内容被转两遍或原地不动。
- ⚠️ `_apply_float_fast()` 末尾**必须把 `_xf_preview_keyframe` 清掉**：否则松手后
  会留着"原图 + 快档矩阵"的快照，而矩阵下一秒被换成精确档那套 ⇒ 画面跳变。
- 快档**只重采样一趟**（不再"缩小→再放大"）⇒ 比精确档**更清晰**；代价是插值
  只能用 Qt 双线性，吃不到 `nohalo/cubic`——所以松手那一帧仍走精确档，
  "预览 == 烘焙"的判据一点没松。
- ⚠️⚠️ **踩坑（已加自测）**：`setClipPath` 是把笔限制在路径**之内**，配
  `CompositionMode_Clear` 必须传**补集**（`outside.subtracted(mapped)`）。
  传原集会清反：该留的透明、该清的留着，画面像内容整块消失。
- 插值分支删了：`_render_float_plane` 已只在非拖动时被调用，"拖动中切 linear"
  成了死代码；`_realtime_budget()` 现在只兜"松手那一帧"。

## 用户第四条报障：「操作框与图片分离 / 画布漂移 / 格子远离」（同日追加）

原话三条：① 格式框没有固定位置，应为原本图片位置，即使图片移动旋转也应是正中心，
**画布画面不变**；② 图片移动旋转后**操作框也应跟着走**，现在是**分离了**；
③ 图片旋转移动时**格子区域块跟图片相互远离**。

### 根因 A（主线）：**Qt `QTransform` 的 `A*B` ＝「先 A 后 B」**（与数学记号相反）

实测 `(A*B).map(p) == B.map(A.map(p))`。而数学写法 `S(k) ∘ placed ∘ S(1/k)`
是**先右后左**。旧代码按数学记号直译：

```python
QTransform().scale(k,k) * placed * QTransform().scale(1/k,1/k)
# 实际算的是 placed(k·u)/k ⇒ 平移量被多除一个 k
```

`k = min(1, sqrt(TRANSFORM_PREVIEW_PIXELS / 选区面积))`，**≤0.5 MP 的选区恒 k=1**
（1/k=1 错误完全抵消）⇒ 旧自测 200×120 / 600×800 **全绿放过了它**。
偏移量 = `t·(1/k − 1)`，实测 920px ⇒ 就是用户说的"操作框跟内容分离"。

修（三处，方向统一为 `S(1/k) * …`）：
- `_preview_placement_xf()` → `S(1/k) * _placed_xf() * S(k)`
- `_float_fast_xf()`（拖动档）→ `S(1/k) * _placed_xf()`
- `_render_float_plane()`：`warp_placement` 返回的 `(x0,y0)` 在预览尺度里 ⇒
  `_xf_preview_origin = (x0/k, y0/k)`（÷k 转回图片坐标）

修后 `_float_fast_xf().map(0,0) == _placed_xf().map(0,0)`，框与内容偏移 **920 → 1px**。

### 根因 B：**场景矩形跟着变换长大 ⇒ 视图漂移**（"画布画面不变"被违反）

`QGraphicsView` 用 `AlignCenter`：`setSceneRect()` 一变，**矩形中心就变 ⇒ 整幅画面平移**。
旧 `_sync_scene_rect` 取「底图 ∪ 浮层」的 bbox，变换把内容送出原边界时矩形长大。

修：`_sync_scene_rect` **恒定 = `image_rect()`**，预览期间绝不再改。
（⚠️ 场景矩形只管滚动条范围、**不影响绘制**——"浮层跑到画外也看得见"不需要扩它。）
量化：绕中心的**纯旋转**因外框对称只漂 **1px**（看不出），**必须带一次平移**才暴露
（转+移实测漂 **294 → 0px**）——这是自测断言设计的关键。

### 自测（`tests/selftests/image_editor.py` 新增 `dialog6`/`canvas6`，7 条）

用 **1000×1400**（>0.5MP ⇒ k≈0.6），**锚点在动手前取**，先 `transform_move(160,-110)`
再 `transform_rotate(20)`（纯旋转对称、测不出漂移）：
① 选区 >预览预算 ⇒ 真走降采样档(k<1)；② 拖动档把区域像素**原样**映到图片坐标
（`_float_fast_xf().map(0,0)==_placed_xf().map(0,0)`）；③ 浮层内容落在变换框上
（`contains` 且边长差≤8）；④ 内容中心恒在轴心；⑤ 转多少圈视图锚点恒定
（`mapFromScene(0,0)` 不变）；⑥ 场景矩形恒定；⑦ 底图（纸）仍恒定 = 原图矩形。

## 第四轮：透视角拖到对角 ⇒ QImage(2.18e9) OverflowError 崩溃（已修）

### 根因（两条防线只修了一条）

### 修法：`geometry.mapped_bounds()` 唯一判据

`(xf, w, h) -> (x0,y0,x1,y1) | None`。None 三条件：坐标非有限（w→0）／
坐标绝对值 > `ABSURD_COORD`=1e8（近共线投影实测 1e9）／外框像素 >
`WARP_MAX_PIXELS`=40MP。**四个入口全部收口**：
1. `warp_region` → None（原有，改走公共判据）
2. `warp_placement` 兜底 → `(QImage(), 0, 0)` 空图不画
3. `compose_transform(grow=True)` → 退回原图边界
4. `transform.py` 透视步进（`transform_perspective` 与拖拽 `_xf_persp`）：
   `mapped_bounds(xf*step)` None ⇒ **整步拒绝、框保持原样**
