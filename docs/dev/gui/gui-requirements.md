# 桌面端需求文档（与 desktop/ 当前实现对齐）

## 1. 用户角色

批量整理古籍扫描 PDF、校正文本框、去底色并生成可交付 PDF 的本地操作人员。
用户无需理解 Python、线程、模型或命令行参数。

## 2. 功能需求

### FR-01 任务管理

- 首页任务列表：**序号（= 任务编号）**、任务名、创建时间、各阶段状态摘要、详情/删除入口（源文件路径不单独成列，仅在任务名悬浮提示中可见）。
  「序号」列直接显示任务号，与排序/搜索/分页无关，方便和任务目录对上号。
- 任务号顺序递增（`0001` 起），即任务目录名；删除后不复用已删除号。
- **导入 PDF**：
  - 后台计算 SHA-256 指纹，与现有任务比对；
  - 发现相同内容 → 弹窗「创建新任务 / 定位已有任务」，取消则定位并选中已有条目；
  - 确认创建的新任务标记 `duplicate_confirmed`；
  - 创建任务后：源文件副本存入任务目录、后台生成逐页缩略图（256px）。
- 任务删除：删除索引 + 任务目录（含全部中间产物）。

### FR-02 任务详情页

- 顶部步骤条四个阶段节点：`extract → detect → rembg → print`；
  当前步骤以主色高亮，已完成步骤显示绿色对勾徽标，未执行灰色；点击切换阶段。
- **历史执行配置**：每个阶段保留最近 20 次执行记录（时间/全量或续跑/状态/完整参数）；
  进入页面自动回填该阶段最近一次参数；下拉选择任意历史记录可一键回填表单。
- 底部执行日志为可折叠面板，实时滚动展示 worker 输出；执行阶段时自动展开，
  出错时摘要与文本标红。

### FR-03 extract（提取图片）

- 将 PDF 每页渲染为图片，直接输出到 `stages/extract/1.jpg…`（无嵌套目录）。
- 参数：缩放因子 zoom、目标 DPI dpi、输出格式 ext、页码范围 pages。
- 整页渲染的 DPI 下限 `dpi` 默认 300（矢量 PDF 在 zoom=1 时只有 72 DPI，
  补下限才能打印清晰）；取内嵌图时按原图落盘，该值不生效。
- 中断后续跑只补缺失页；渲染时上报每页图片原始尺寸（写入 `sizes.json`）。

### FR-04 detect（检测文本框）

- YOLO（`functions.detect.detect_page_boxes`，底层 `utils.yolo_utils.detect_left_right_boxes`）
  识别每页左右文本框坐标；**只检测，不生成文件**。
- 检测算法与 CLI 的 `detect` / `crop` / `cropremove` **同源**，因此两个入口
  看到的框完全一致（没有第二份实现）。
- 检测结果实时写入 `boxes.json`（保留左/右身份）；预览叠加显示，可编辑。
- 切换到本阶段**不自动执行检测**（重负载）；提供「检测本页」按钮手动触发，
  或执行本子任务批量检测。

### FR-05 rembg（图片去底色）

- 整页 Otsu 去底（二值/1bit/灰度），可保留印章（seal/sealcolor）。
- **area/border 参数在本阶段**：决定预览与裁剪区域（规则同 CLI crop/cropremove，
  见 technical-spec）。
- 预览：单视图；有去底色结果默认显示结果，顶部可切换原图；无结果时显示原图。
- area=1 时左侧条目按输出拆分（`N-r`、`N-l`），排序遵循 CLI natural sort
  （同页 r 在 l 前），条目标题为排序后序号 1,2,3…；条目缩略图只显示所属框区域。

### FR-06 print（生成 PDF）

- 左侧为待打印图片缩略图条（第三步去底色结果初始化）：
  拖动排序、删除条目、插入外部图片；列表持久化（print.json）。
- 右侧上方是**打印效果预览**：按当前参数把选中页排进一张纸给用户看，
  **只是效果，不执行、不提交、不生成 PDF**；顶部「打印效果 / 原图」可切换。
  预览几何与最终 PDF 共用 `utils.page_layout.plan_print_page`。
- 右侧为**参数表单**（分「输出与纸张 / 页边距 / 标题排版 / 页码 / 过滤」五组），
  含「恢复默认配置」「放弃本次修改」两个按钮。print 参数较多，表单按分组排布并支持独立滚动；
  完整参数清单见 [gui-technical-spec.md](gui-technical-spec.md)。
  参数覆盖：pdf_name、纸张/方向/页边距、标题（含切换节点、**距页边**）、
  页码（含**距页边**）、跳过页等；input/output/workers/clean 由系统管理，
  不在表单范围内。
- **标题/页码的「位置」「文字方向」不在表单内**：
  标题恒 `top`、页码恒 `bottom`、两者恒 `vertical`，由
  `PrintFormMixin.FIXED_TEXT_LAYOUT` 兜底导出。理由：既然「距页边」已经把
  标题固定在上边（只摆「上边距」一行）、页码固定在下边（只摆「下边距」一行），
  再给一个「位置：上边/下边」的下拉就自相矛盾——要么让两者动态联动、
  要么干脆取消这两个参数，这里选后者（古籍定式：书名在版框之上、
  页码在版心之下，都是竖排）。
  ⚠️ 桌面端**不改写**历史参数里这两个键：`_apply_args` 把读到的值记进
  `_fixed_layout_echo`，`get_args` 原样回显，避免「参数暂存」把老任务的
  `horizontal` 静默改成 `vertical`（用户没动任何控件，配置却变了）。
- 标题/页码的「距页边」是**距纸张边界**的绝对距离（mm，上/右/下/左）：
  左页取「左」值、右页取「右」值，位置在上边/下边时分别取「上」/「下」值。
  留空（None）回落到由 page_margins 推导的旧行为。
  表单不让你写一串数字，**就两行、每行一个通栏输入框**：
  第一行「左右边距：」= 一个值同时管左页（贴左纸边）与右页（贴右纸边），
  所以左右对称；第二行「上边距：」/「下边距：」= 纵向那一个值。
  ⚠️ 只摆**用得上的**那两个分量——标题在上边就永远读不到「距下」，页码在下边
  也永远读不到「距上」，四个框全摆出来会让人以为四个都得填（`INSET_VISIBLE`）。
  另有**实时释义**（"文字轮廓距左右纸边各 10mm｜距上 2mm"）。
  不勾选 = 留空 = 老行为；参数值本身仍是四值（`title_margins` 等契约不变），
  界面缺席的那个纵向分量由 `_inset_values` 按「底层读不到 → 补 0」导出，
  **不会把输入框的显示初值混进参数**；横向那一个框回填时取**左页值**
  （同一个控件对象同时登记 left/right，逐个回填会互相覆盖）。
- ⚠️ **不再自动避让图片**：填了距离就按距离画文字，**允许压在图片上**；
  图片左右只留固定的 `TEXT_MARGIN_MM`（8mm），不随「距页边」变化。
- **参数暂存**：改了参数没执行就切阶段/切任务/关程序，改动不丢——
  落 `drafts/<阶段>.json`，下次进入该阶段按 **暂存 > 最近一次执行参数 > 默认**
  回填。
- **竖排里的拉丁字符整段旋转 90°**（`utils.page_layout.vertical_runs`）：汉字一字
  一格，ASCII 段连成一段旋转，预览与成品共用同一份分段规则。

- 执行时按列表顺序物化输入（顺序命名 0001…），页序与列表严格一致；
  pdf_name 缺省时自动补 "print.pdf"。

### FR-07 检测框编辑

- 预览中可拖动、四角缩放、Delete 删除、空白处手绘新框；
- 编辑结果实时写入 `boxes.json`（origin=manual），**不生成任何文件**；
- 手动结果不被自动检测结果覆盖。

### FR-08 页面增删

- 从页面清单删除页面、在指定位置插入外部图片（复制到 `stages/extract`）。

## 3. 非功能需求

- **性能**：切换阶段/翻页不卡顿（重负载全部在 worker 线程；缩略图直读预生成
  小图；原始分辨率处理仅在 worker 线程）。
- **健壮性**：worker 崩溃/中断可见（日志 + 失败原因）；中断可续跑；
  缩略图缺失自愈（完成后核对补齐）。
- **可移植**：数据目录 `~/Documents/guji`；纯 JSON 文件存储，无数据库依赖。
- **一致**：检测框/区域规则与 CLI 单一实现（`utils/box_geometry.py`），
  GUI 与 CLI 行为不漂移。
