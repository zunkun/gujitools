# 桌面端需求文档（与 desktop/ 当前实现对齐）

## 1. 用户角色

批量整理古籍扫描 PDF、校正文本框、去底色并生成可交付 PDF 的本地操作人员。
用户无需理解 Python、线程、模型或命令行参数。

## 2. 功能需求

### FR-01 任务管理

- 首页任务列表：**序号（= 任务编号）**、任务名、创建时间、各阶段状态摘要、详情/删除入口（源文件路径不单独成列，仅在任务名悬浮提示中可见）。
  「序号」列直接显示任务号，与排序/搜索/分页无关，方便和任务目录对上号。
- 任务号顺序递增（`0001` 起），即任务目录名；删除后不复用已删除号。
- **创建任务**（二级页面，不是弹窗）：任务名 + 可选 PDF + 流程选择。
  - **任务名非必需**，默认「任务#XXXX」（XXXX = 任务号，创建时按实际分配到的号
    现算）；留空且选了 PDF ⇒ 用 PDF 文件名；留空且没选 PDF ⇒ 用默认名。
    建完后可在详情页页头随时改名。
  - **PDF 非必需**：「创建任务」按钮不因"还没挑文件"而灰。没选 PDF 建出来的
    是**空壳任务**，详情页页头显示「尚未选择 PDF」并提供补选入口。
  - **已选文件可一键清除**：选择框旁的「⊘」按钮，仅在已选时出现。清除后任务名里
    那个自动填的文件名一起回退（用户自己改过的名字保留）。
  - **流程需要 PDF 而用户没给时，先问一句**（用户 2026-10-06）：给「现在选择」
    /「先不传」两条路——两条都合法，不拦住不让建。判据是**当前流程图**里有没有
    直接吃源 PDF 的阶段（自定义流程删掉「提取图片」就不问）。
  - 选了 PDF 时：后台计算 SHA-256 指纹，与现有任务比对；发现相同内容 → 弹窗
    「创建新任务 / 定位已有任务」，取消则定位并选中已有条目；确认创建的新任务
    标记 `duplicate_confirmed`；创建后源文件副本存入任务目录、后台生成逐页
    缩略图（256px）。
  - **缺输入的提示**（用户 2026-10-06）：分两类，提示的样子跟着"缺什么"变——
    - **缺 PDF**（流程里有吃 PDF 的步骤、任务还没选）：页头 **PDF 按钮高亮**、
      红字说 PDF、进任务弹一层**页内提示**（遮罩盖住流程条与内容区、卡片居中、
      可当场选文件；**页头与右上角按钮留在遮罩之上、照常可点**）。
    - **缺入口图片**（流程第一步**不是**图片提取那类节点、且输入目录里没图）：
      同样三重提示，但**高亮的是图片按钮**、红字与弹窗都说"图片"，弹窗按钮是
      「选择图片」；页头新增**图片按钮**作为插图入口（预览区的「＋」会被遮罩
      盖住，页头这一排永远可点）。也可以直接把图片/图片文件夹拷进任务目录下
      的 `stages/input`。
    - 两者都缺时**先说 PDF**。补上后提示全部收回；**每次进入该任务都会重新检测**。
  - **补选/更换 PDF**（详情页页头，图标用 PDF 样式的图标）：**先算指纹再决定**——
    ①就是当前这个文件 ⇒ 不动；②已在别的任务里 ⇒ **提示已存在相同文件任务、问是否
    继续**（与创建任务时的查重确认一致），答「仍然使用」就换；③是新 PDF ⇒ 先确认
    （换源会清空后续节点数据），确认后才换。
- 任务删除：删除索引 + 任务目录（含全部中间产物）。

### FR-02 任务详情页

- 顶部步骤条四个阶段节点：`extract → detect → rembg → print`；
  当前步骤以主色高亮，已完成步骤显示绿色对勾徽标，未执行灰色；点击切换阶段。
- **回到上次停留的步骤**：每个任务记住用户最后停留的那一步（任务目录
  `ui.json`），下次打开任务详情默认打开它；没有记录、或记录的那一步在当前
  流程里匹配不上时，从第一步开始。
- **启动不自动跳回上次任务**：程序启动后停在任务列表页，不自动进入上次执行
  的任务（2026-10-06 改口径）；用户点进某个任务时仍落到该任务上次停留的步骤。
- **历史执行配置**：每个阶段保留最近 20 次执行记录（时间/全量或续跑/状态/完整参数）；
  进入页面自动回填该阶段最近一次参数；下拉选择任意历史记录可一键回填表单。
- 底部执行日志为可折叠面板，实时滚动展示 worker 输出；执行阶段时自动展开，
  出错时摘要与文本标红。

### FR-03 extract（提取图片）

- 将 PDF 每页渲染为图片，直接输出到 `stages/extract/1.jpg…`（无嵌套目录）。
- 参数：缩放因子 zoom、目标 DPI dpi、输出格式 ext、页码范围 pages。
- 整页渲染的 DPI 下限 `dpi` 默认 300（矢量 PDF 在 zoom=1 时只有 72 DPI，
  补下限才能打印清晰）；取内嵌图时按原图落盘，该值不生效。
- 中断后续跑只补缺失页；渲染时上报每页图片原始尺寸（写入 `sizes.json`）。

### FR-04 detect（检测文本框）

- YOLO（`functions.detect.detect_page_content`，底层 `utils.yolo_utils.detect_content_boxes`）
  识别每页内容框坐标（半幅 harfcontent 左右两栏 / 整幅 fullcontent 单区）；**只检测，不生成文件**。
- 检测算法与 CLI 的 `detect` / `crop` / `cropremove` **同源**，因此两个入口
  看到的框完全一致（没有第二份实现）。
- 检测结果实时写入 `boxes.json`（半幅恒 2 槽 `[左, 右]`、整幅 1 槽 `[整幅]`）；
  预览叠加显示，可编辑。
- **人工干预**：框的类型是框自己的属性——半幅的左/右按**中心位置**判定（拖动跨过
  中线自动换边），「整幅」在面板「选中框类型」里**显式选择**且不受位置/大小影响；
  整幅与半幅互斥、整幅一页只能一个框（越界时弹确认框可删除其他框）。
  删掉一个框不影响其他框的类型。
- **「保留框外空白」（任务级参数，默认"不保留"）**：保留时预览上画的就是**扩展框**
  ＝「保留空白后要裁的区域」——左右双框以两框相邻边界的中点分界、单框以框的
  **内侧边**分界，上下与外侧都到图片边缘；整幅/单栏页整页一张。
  - **无框页按全书统计补框**（用户 2026-11-12）：判据唯一实现＝
    `book_layout.keep_blank_page_form(page_w, typical_w, half_w, expects_two, has_stats)`
    → `"split"` / `"single"` / `"skip"`；显示侧 `DetectMixin._blank_page_policy`
    与提交侧 `print_plan.plan_detect_submit_entries` **调同一个函数**。
    - `split`：双栏书（`profile.double_column_book`，≥90% 有框页是左右两框）**且**
      本页装得下两个框（`fits_two_boxes`：`page_w ≥ 2 × half_width × typical_w × 1.02`）
      ⇒ 按页宽中线拆左右两张；
    - `single`：只装得下一个（单页扫描）/ 单栏书 / 整幅书 / 混排 ⇒ 整页一张；
    - `skip`：整本书一个框都没有（`profile.boxed_pages == 0`）⇒ 不补，仍走原占位/透传。
    统计素材在 `_refresh_detect_stats` 里缓存为 `_blank_typical_width /
    _blank_half_width / _blank_expects_two / _blank_has_stats`；**`set_task` 与
    「没有页」的早退分支必须清零**，否则换书后空白页会按上一本的框宽被凭空拆两半。
  - **单框页也有"装不装得下"这一条**：双栏书里只检出一侧、本页装得下两个 ⇒ 保留
    2 槽（分界线落在检出框的**内侧边**，即用户说的"分割线在能识别的那个文本框
    边缘"）；装不下 ⇒ 退成单槽＝整页一张。唯一实现 `book_layout.keep_blank_slots`。
  - **作用域＝当前任务**（用户 2026-11-12：「参数是任务级别的，不是整个系统一个
    参数，任务 A 的设置不影响任务 B」）：值落 `tasks/<任务号>/ui.json` 的
    `detect_keep_blank`（`store.load_detect_keep_blank` / `save_detect_keep_blank`），
    **不是**按节点分的 `drafts/<阶段>~<节点>.json`；`drafts.DRAFT_SKIP` 已排除该键
    ⇒ 单一事实来源。回填优先级 **任务级 > 暂存 > 历史 > 默认**
    （`HistoryMixin._apply_task_scoped_params`，在 `_restore_stage_params` 末尾覆盖；
    `None`＝这个任务没设过，不许当成 `False` 覆盖历史）；
    `DetectMixin._keep_blank_on()` **只读面板现值**，绝不去读任何全局配置
    （那正是串味的来源）。默认值 `params_spec.DETECT_DEFAULTS["keep_blank"]=False`。
  - 显示：绿＝左框、蓝＝右框，带「左框/右框(+坐标)」文字；**相邻两框共用的那条
    竖线只画一次**（`SHARED_EDGE_COLOR`＝**朱红** `#e11d48`）。中性灰试过不行：
    用户 2026-11-12「看着是黑色或者灰色，不明显」——分界必须是与左右框都不同的
    强调色，才读得出"这是分界"；
  - 描边：未选中 2px／选中 3px；**绘制矩形按半个线宽向内收**（`_draw_boxes`），
    否则贴在图片边缘那几条边有一半落在 pixmap 外（"没画出来"）；
  - **任何页面都能手画扩展框**（含没有检测结果的空白页）：`save_blank_regions`
    在该页没有条目时会补一条 `boxes: []` 的，否则手画完静默丢掉；
  - **可调整**：扩展框可直接拖动（改分界、改区域大小）⇒ 存 `boxes.json` 的
    `blank`（`store.save_blank_regions`），**检测框不动**；提交侧
    `plan_detect_submit_entries(blank_for=…)` 优先用它。自动重检（origin=auto）
    会清掉 `blank` ＝ 回到自动；
  - **类型按钮改的也是扩展框**（`_set_blank_region_kind`）：「整幅」并成整页一张，
    「左框/右框」按页中线拆两半，「半幅」对扩展框无意义（只提示）；
    「删除选中框」删的是选中的那块扩展框；**最后一个也能删**，删空后这页退回
    「整页一张」（不能留空——这页没有裁图产物会让整本书少一页）；
  - ⚠️ `full` 标记（框数上限/标签）判据＝**只剩一块且这块宽≥60%页宽**
    （`is_single_wide_box`）。绝不能按"只剩一个"判——删掉一侧后剩下的那半也是
    "一个"，那样左框/右框会错显成整幅（用户 2026-11-12 报的 bug）。
  - 它**进提交产物的版本判定**：改了就要重新「提交本次任务」。
- 面板布局按**作用域**分两组（用户 2026-11-11，作用域 2026-11-12 明确为任务级）：
  `SectionTitle「本任务参数」`（保留框外空白：标题加粗独占一行 + 开关铺满整行 +
  **两态都有**一行取值说明）→ 空白 + 2px `T.SEPARATOR` 分隔线 + 空白 →
  `SectionTitle「本页参数」`（检测本页 / 选中框类型 / 删除选中框）。
  分组标题与右侧「检测结果统计」同款。⚠️ 不要再写「全局参数」——那是"整个软件
  一个开关"的语义，与"任务级"正好相反（用户 2026-11-12 明确否认）。
- 切换到本阶段**不自动执行检测**（重负载）；提供「检测本页」按钮手动触发，
  或执行本子任务批量检测。

### FR-05 rembg（图片去底色）

- 整页 Otsu 去底（二值/1bit/灰度），可保留印章（seal/sealcolor）。
- **area/border 参数在本阶段**：决定预览与裁剪区域（规则同 CLI crop/cropremove，
  见 technical-spec）。
- 预览：单视图；有去底色结果默认显示结果，顶部可切换原图；无结果时显示原图。
- area=1 时左侧条目按输出拆分（`N-r`、`N-l`），排序遵循 CLI natural sort
  （同页 r 在 l 前），条目标题为排序后序号 1,2,3…；条目缩略图只显示所属框区域。

### FR-06 print（PDF排版）

- 左侧为待打印图片缩略图条（第三步去底色结果初始化）：
  拖动排序、删除条目、插入外部图片；列表持久化（print.json）。
- 右侧上方是**打印效果预览**：按当前参数把选中页排进一张纸给用户看，
  **只是效果，不执行、不提交、不生成 PDF**；顶部「打印效果 / 原图」可切换。
  预览几何与最终 PDF 共用 `utils.page_layout.plan_print_page`。
- 右侧为**参数表单**（分「输出与纸张 / 页边距 / 标题排版 / 页码 / 过滤」五组），
  含「恢复默认配置」「放弃本次修改」两个按钮。print 参数较多，表单按分组排布并支持独立滚动；
  完整参数清单见 [gui-technical-spec.md](gui-technical-spec.md)。
  参数覆盖：pdf_name、纸张/方向/页边距、标题（含切换节点、**距页边**）、
  页码（含**距页边**）、跳过页等；input/output/workers/clean 由系统管理，
  不在表单范围内。
- **标题/页码的「位置」「文字方向」不在表单内**：
  标题恒 `top`、页码恒 `bottom`、两者恒 `vertical`，由
  `PrintFormMixin.FIXED_TEXT_LAYOUT` 兜底导出。理由：既然「距页边」已经把
  标题固定在上边（只摆「上边距」一行）、页码固定在下边（只摆「下边距」一行），
  再给一个「位置：上边/下边」的下拉就自相矛盾——要么让两者动态联动、
  要么干脆取消这两个参数，这里选后者（古籍定式：书名在版框之上、
  页码在版心之下，都是竖排）。
  ⚠️ 桌面端**不改写**历史参数里这两个键：`_apply_args` 把读到的值记进
  `_fixed_layout_echo`，`get_args` 原样回显，避免「参数暂存」把老任务的
  `horizontal` 静默改成 `vertical`（用户没动任何控件，配置却变了）。
- 标题/页码的「距页边」是**距纸张边界**的绝对距离（mm，上/右/下/左）：
  左页取「左」值、右页取「右」值，位置在上边/下边时分别取「上」/「下」值。
  留空（None）回落到由 page_margins 推导的旧行为。
  表单不让你写一串数字，**就两行、每行一个通栏输入框**：
  第一行「左右边距：」= 一个值同时管左页（贴左纸边）与右页（贴右纸边），
  所以左右对称；第二行「上边距：」/「下边距：」= 纵向那一个值。
  ⚠️ 只摆**用得上的**那两个分量——标题在上边就永远读不到「距下」，页码在下边
  也永远读不到「距上」，四个框全摆出来会让人以为四个都得填（`INSET_VISIBLE`）。
  另有**实时释义**（"文字轮廓距左右纸边各 10mm｜距上 2mm"）。
  不勾选 = 留空 = 老行为；参数值本身仍是四值（`title_margins` 等契约不变），
  界面缺席的那个纵向分量由 `_inset_values` 按「底层读不到 → 补 0」导出，
  **不会把输入框的显示初值混进参数**；横向那一个框回填时取**左页值**
  （同一个控件对象同时登记 left/right，逐个回填会互相覆盖）。
- ⚠️ **不再自动避让图片**：填了距离就按距离画文字，**允许压在图片上**；
  图片左右只留固定的 `TEXT_MARGIN_MM`（8mm），不随「距页边」变化。
- **参数暂存**：改了参数没执行就切阶段/切任务/关程序，改动不丢——
  落 `drafts/<阶段>.json`，下次进入该阶段按 **暂存 > 最近一次执行参数 > 默认**
  回填。
- **竖排里的拉丁字符整段旋转 90°**（`utils.page_layout.vertical_runs`）：汉字一字
  一格，ASCII 段连成一段旋转，预览与成品共用同一份分段规则。

- 执行时按列表顺序物化输入（顺序命名 0001…），页序与列表严格一致；
  pdf_name 缺省时自动补 "print.pdf"。

### FR-07 检测框编辑

- 预览中可拖动、四角缩放、Delete 删除、空白处手绘新框；
- 编辑结果实时写入 `boxes.json`（origin=manual），**不生成任何文件**；
- 手动结果不被自动检测结果覆盖。

### FR-08 页面增删

- 从页面清单删除页面、在指定位置插入外部图片（复制到 `stages/extract`）。

### FR-09 图片拼版（可选节点）

仅在第三步「区域模式 = 1（左右分开）」时出现——流程条「图片去底色」与
「PDF排版」之间的**虚线可选节点**；用户可以选择也可以不选择。

- **左侧一列**：「第一页 / 第二页 / …」，最后一格是**虚线**的「＋ 选择拼版」；
- 点它弹窗，从**剩余未被选择拼版的图片**里挑**两张**；
  源清单顺序在前的那张落在拼版页**右侧**（古籍右起）；来源是第三步
  「提交本次任务」的成品图；
- **右侧操作区**：**纯白底、无纸张**（不设纸张尺寸），**点击某张图选中**
  （选中图带常显细虚线，切页/点空白取消选中）、拖动移动、四角缩放
  （Shift 等比）、四边单独拉伸、**框外上方圆钮旋转**（选中后常显，
  **在图片外面**按住左键拖它即绕图心旋转选中的那张图；Shift 吸附 15°）；
  面板分两块：页级**「操作当前图片页」**（整体旋转/复位本页版面/
  删除/清空，复位与删除**同行**；删除、清空**弹窗确认**——版面调整丢失，
  不可撤销）与图片级**「操作当前图片」**（旋转）——
  后者**只在有选中图时激活高亮**；说明收在标题旁**问号按钮**里，
  **「在流程中启用图片拼版」开关放面板最底部**（2026-09-30 口径）。
  ⚠️ **位置与大小都不设范围限制**
  （图可以拖出可视区、拉得比原图大），产出图 = **所有图外接框的紧裁**；
- 翻页用**画布下方右侧**的「上一页 / 下一页」；页序在左列**拖动排序**——
  **顺序即最终 PDF 页序**；
- **生效规则**：勾选「在流程中启用图片拼版」且至少有一页拼版时，第四步
  待打印列表与「生成PDF」改用拼版结果（`stages/imposition`）；否则仍用
  第三步去底色产物（`stages/rembg`）。拼版不是必经步骤。

## 3. 非功能需求

- **性能**：切换阶段/翻页不卡顿（重负载全部在 worker 线程；缩略图直读预生成
  小图；原始分辨率处理仅在 worker 线程）。
- **健壮性**：worker 崩溃/中断可见（日志 + 失败原因）；中断可续跑；
  缩略图缺失自愈（完成后核对补齐）。
- **可移植**：数据目录 `~/Documents/guji`；纯 JSON 文件存储，无数据库依赖。
- **一致**：检测框/区域规则与 CLI 单一实现（`utils/box_geometry.py`），
  GUI 与 CLI 行为不漂移。
