# 桌面端交互设计（与 desktop/ 当前实现对齐）

## 1. 任务列表页

- 卡片头部：标题 + 「创建任务」按钮（点它进**创建任务二级页**，不是弹窗）；
  表格：序号/任务名/创建时间/阶段状态摘要/操作（源文件路径不单独成列，仅在
  任务名悬浮提示中可见）。
  「序号」列显示的是**任务自己的编号**（`0001`、`0002`…，即索引主键与任务目录名），
  不是行号——排序、搜索、翻页都不改变它，用户拿它就能对上 `tasks/<编号>` 目录。

### 1.1 创建任务页（二级页）

    [← 任务管理]
    任务名称  [ 一本古籍            ]   ← 33px 高、最多 360px、placeholder＝任务#0007
    留空则使用 PDF 文件名「×××」。           ← 提示随"填没填/选没选 PDF"变
    [ ] 使用自定义任务流程
    PDF 源文件：[选择文件…]  已选择：xxx.pdf (⊘)   ← ⊘=清除，仅已选时出现
                          没选时显示「可留空，之后在任务详情里补选」
    当前流程：…（节点图照flow.bpmn 渲染）
    [取消]                          [创建任务]   ← 后者**恒可点**

- **任务名非必需**：留空 + 有 PDF ⇒ 文件名；留空 + 无 PDF ⇒「任务#XXXX」。
  默认名里的序号在**落库那一刻**按实际分配到的任务号现算（占号是原子的、可能
  顺延，用预测值会让「任务#0008」落在 0009 号任务上）。
- **每次进入都复位**（用户 2026-10-06 报障）：本页是**惰性单例**（建一次长期
  留着），`ModuleShell.open_create` 每次都调 `CreateTaskPage.reset()`——清任务名、
  已选 PDF、勾选、自定义流程图（回初值）、开着的流程编辑器、`_busy` 与控件禁用
  态，并**重算**默认名占位（刚才那次创建已占掉一个号）。不复位的话，第二次建
  任务等于接着上一次半途而废的表单继续填。⚠️ 复位放在"已经在这一页"的判断
  **之前**——连着点两次「创建任务」第二次也要清。
- **PDF 非必需**：「创建任务」按钮不因"还没挑文件"而灰。空壳任务进详情页后
  页头显示「尚未选择 PDF」并有补选按钮；执行任一步会提示去那里补。
- **选错文件能一键清掉**（用户 2026-10-06）：PDF 那行有个「⊘」清除按钮，
  **只在已选时出现**、**紧贴文件名**（丢在行末看不出它管的是哪个文件）；
  文件名文字有宽度上限（`PDF_STATE_MAX_WIDTH`），长书名不会把按钮顶出窗口。
  清除时**任务名里那个自动填的文件名一起回退**——但只回退"仍等于该
  stem"的情况，用户自己改过的名字不碰（那是丢用户输入）。
- **⚠️ 但「流程要 PDF 而用户没给」要先问一句**（用户 2026-10-06）：点
  「创建任务」时弹一次确认，给两条路——「现在选择」（顺手开选择框，选中即
  直接建，不用再点一次）/「先不传」（照常建空壳任务）。**不是拦住不让建**：
  两条路都合法。判据是**当前这张流程图**里有没有直接吃源 PDF 的阶段
  （`StepSpec.needs_source_pdf()`＝端口声明 `inputs` 含 `pdf`；用户自定义流程
  删掉「提取图片」就不问了），别拿 `input_noun()` 判——四步里三步都写
  "选择图片"。
- 提交后的链路与旧「导入 PDF」完全一致（指纹 → 查重 → 建任务 → 后台复制 +
  缩略图 → 直接进详情），只是入口换成了页面。

- 有 PDF 时的导入链路：后台算指纹 → 查重：
  - 无重复 → **立刻建任务并刷新列表**（主线程只写一个 `tasks.json`，毫秒级）；
  - 有重复 → 弹窗「创建新任务 / 定位已有任务」；取消则选中已有条目并提示。
- 导入后的重活全在**后台串行队列**里（`desktop/workers/serial_jobs.py`）：
  「复制源文件副本 + 逐页渲染缩略图」。两条硬约束（实测见 `.workbuddy/perf/`）：
  ① 同一时刻只跑一个——多个 PyMuPDF 渲染线程并行会争抢 GIL，把主线程的
  `create_task` 从 5ms 拖到 929ms（中位）；② **等列表行画完再开工**——列表回程要读
  N 个任务的 `runs.json`，撞上渲染线程时「导入 → 看见新行」会从 0.2s 变成 0.5~2.5s。
  ⚠️ **空壳任务不排队任何后台活**（没有文件可渲，硬排会报错并卡住串行队列）。
- 后台活进行期间，**页头副标题**换成「正在导入 · 缩略图 12/123 · 书名 +N 排队」，
  干完恢复默认说明并提示「导入完成」。⚠️ 别用 `InfoBar(duration=-1)` 做长驻提示：
  qfluentwidgets 的 `InfoBarManager` 在 `showEvent` 里登记，控件隐藏再显示会重复登记，
  留下悬垂条目，之后任何 toast 自动关闭都会刷 `Internal C++ object already deleted`。
- 行内操作：详情（进入任务页）、删除（确认框）。

## 2. 任务详情页

- 顶部：返回按钮、任务名（铅笔按钮行内改名）、源文件名、**选择/更换 PDF**
  按钮（图标用自绘的 `PDF_FILE`，不是内置的空白 `DOCUMENT`）、查看/编辑流程、
  打开数据目录。
- **源文件三态要分清**（`source_path`）：`None` = 还没选（空壳任务，显示
  「尚未选择 PDF」+ 补选入口）／路径在但文件不在 = 文件丢了（红色错误 +
  补选入口）／正常。别拿一个 `exists()` 覆盖三种——`Path("")` 是`.`（当前
  目录），空路径会被误判成"文件在"。
- **「缺输入」有两类，别混**（用户 2026-10-06）：
  | 缺什么 | 什么时候 | 提示长什么样 |
  |---|---|---|
  | 缺 **PDF** | 流程里**有**吃 `pdf` 端口的阶段（`ports.flow_needs_source_pdf`），而任务 `source_path is None` | 高亮 **PDF 按钮**＋红字说 PDF＋提示层「现在选择」去选 PDF |
  | 缺 **入口图片** | 流程的**入口阶段不吃 PDF**（`ports.flow_needs_entry_images`）**且** `stages/input/` 里没有图 | 高亮 **图片按钮**＋红字说图片＋提示层「**选择图片**」 |

  统一判据是 `TaskDetailPage._missing_input_kind()` → `"pdf"` / `"images"` / `""`
  （**PDF 优先**）。⚠️ 所有"缺输入"的表现（按钮高亮 / 页头红字 / 提示层文案 /
  执行守卫 / toast）**都读这一个判据**——散开各判各的，漂移起来就是
  "红字说缺图、弹窗说缺 PDF"。
  ⚠️ `MissingSourcePrompt` 的文案与按钮由**宿主传入**
  （`configure(**_source_prompt_content())`）：组件里写死"缺 PDF"的说法，对
  "流程第一步是检测"的用户就是错的引导。⚠️ 每次显示前**必须刷文案**（提示层
  对象会复用，缺的东西会变）。
- **入口图片从哪来**（自定义流程第一步不吃 PDF 时）：
  沿图回溯不到上游 ⇒ `store.stage_input` 回落 `stages/input/`
  （`ports.resolve_input_with_entry`，**只对 `pages` 端口回落**）。
  落点由 `ports.TASK_INPUT_LOCATION` 唯一声明。三条路都通：
  ①页头**图片按钮**（`FIF.PHOTO`）→ `insert_pages`（选文件，复制进
  `stages/input/`）——⚠️ 放**页头**是因为预览区的「＋」会被提示层遮罩盖住，
  页头这一排永远在遮罩之上；②直接把图/图文件夹拷进 `stages/input/`；
  ③`stages/input` 里已有图 ⇒ `_missing_input_kind()` 返回 `""`，提示全收。
- ⚠️⚠️ **执行守卫问"这一步的输入齐不齐"，不是"有没有 PDF"**
  （`runner._stage_inputs_ready`，`submit` 同一份）：此前写死
  `not self.source_path`，于是"流程第一步是检测"的任务**图都放好了也点不动**
  ——守卫比流程还严。判据走 `ports.stage_inputs` + `store.stage_input`，
  任一输入端口解析不出可用路径才算不齐。
- **「缺源 PDF」的三重提示**（缺 PDF 那一类，判据
  `flow_needs_source_pdf` AND `source_path is None`）**成立时三件事同时做：
  ①页头 **PDF 按钮高亮**（红边框 + `DANGER_SOFT` 淡红底，⚠️ 用样式表而不是
  换成 `PrimaryPushButton`——那会让这一排工具按钮**尺寸**变掉、页头被撑变形）；
  ②页头出**红字**（`source_warning`，放页头而不是 toast：toast 会自己消失，
  而这件事在补上文件前一直成立）；
  ③每次进这个任务详情页弹出一层**页内提示**
  （`components/missing_source_prompt.py::MissingSourcePrompt`，**非模态**）。
  补上文件后三者**全部收回**。
  - ⚠️③**不用 `MessageBox`**，用户截图三条各否掉它一个理由：库的
    `MaskDialogBase` 只在**构造那一刻**读一次 `parent.width()/height()`（遮罩
    只盖住左上角一小块）、它铺满 parent 所以**留不下页头**、它是**模态**的所以
    **页头按钮点了没反应**（用户原话："那个导入按钮，你不能把它给遮住啊"）。
  - 提示层只盖「步骤条及其以下」（`_content_top`＝**页头下沿 + 间距**）；页头与
    右上角那排按钮留在遮罩之上、**照常可点**（自测用 `QTest.mouseClick` 真点过，
    `_on_pick_source` 确实被调）。
  - ⚠️ 遮罩上沿**不能读步骤条的 `geometry()`**：它刚被 `_rebuild_step_bar` 换掉、
    布局还没定位，读出来是 QWidget 默认的 640×480、`mapTo` 得 0，连
    `layout.activate()` 都不管用（`removeWidget`+`insertWidget` 之后不重排）。
    页头卡片是稳定的，用它算。
  - 遮罩把内容区的点击**吃掉但不关提示**：用户点内容区多半是想按某个按钮，
    那里关掉提示会造成"提示没了、按钮又没反应"，比单纯"没反应"更困惑。
    关提示只有「稍后再说」一个入口。
  - ⚠️⚠️ **重铺时机必须有 `showEvent`**（用户 2026-10-06 报"第一次进入没有弹窗、
    第二次才有"）：`ModuleShell.open_detail` 是**先 `set_task()`、后
    `setCurrentWidget()`**，所以 `set_task` 里弹提示层的那一刻详情页刚被
    `addWidget` 进栈、**还没布局**——尺寸是 QWidget 默认的 `640x480`、
    `_content_top()` 返回布局未跑时的垃圾值（实测 491）⇒ 遮罩高度被夹成 **0**，
    看上去就是"压根没弹"，而第二次进入才正常（尺寸已对）。
    三处配合才彻底：①`showEvent` 里重铺（布局与尺寸就绪的第一个时刻，
    `QStackedWidget` 切页是先 resize 再 show）；②`resizeEvent` **不许**用
    `prompt.isVisible()` 当条件（那一刻页面还没 show，`isVisible()` 看整条祖先
    链恒为 False，恰好把"首次进入"这一路拦掉）；③`_reanchor` 在上沿大到不像话
    （超过页高 60%）时**放弃这一次**——宁可晚铺，也不写一个错的上去。
    ⚠️ `showEvent` 里**必须先判 `task_id`**：`addWidget` 那一下就会触发它，
    早于第一次 `set_task`，此时 `task_id` 是 `None`，而 `_missing_source()` 会拿
    它去查流程图 → `store.task_dir(None)` 抛 `ValueError`（自测被它打断过）。
  - 卡片**高度用 `heightForWidth`**：`sizeHint` 给的是**未换行**的高度，按它摆
    ⇒ 文字被裁一截（实测 181 vs 211）。
  - 卡片**可拖动**（按住空白处），拖出提示层范围会被夹住。⚠️ 判"能不能拖"要看
    那一点是不是**按钮**（`isinstance(child, QAbstractButton)`），**不能**用
    `childAt(...) is None`——卡片上有说明文字标签，`childAt` 会返回它，于是
    "空白处"永远判不成立、拖动完全失效。⚠️ 过滤器**只装在卡片上**：装到按钮
    上再吞 MouseButtonPress 会让按钮**点了没反应**（QAbstractButton 收不到
    press 就不会发 clicked）。
- **补选/更换 PDF 先算指纹再决定**（用户 2026-10-06）：几百 MB 的 PDF 算一次
  SHA-256 要一两秒，所以指纹**走后台**（`HashWorker`），算完分三条路——
  ①**就是当前这个文件** ⇒ 什么都不做；②**已在别的任务里** ⇒ **问一句
  "是否仍然使用"**，用户答"仍然使用"才换（⚠️ **不是一律拒绝**，与列表页的
  查重确认同一态度）；③**是新 PDF** ⇒ 换源**之前**问一句，确认后才换。
  ⚠️ ②③**不要连弹两次**（清空后果写进同一个弹窗）。算指纹期间按钮锁住并把提示
  改成"正在读取…"，免得用户以为没点上。
  ⚠️ `MessageBox` 是**纯文本**、不解析 markdown——文案里写 `**` 粗体会让用户
  看到一串星号。
- **更换 PDF 会清空中间产物**（页清单/执行记录/检测框/阶段输出/页缩略图
  缓存），有产物时先确认；流程图 `flow.bpmn` 不动（那是用户配的，与书无关）。
  ⚠️ 清产物**连"待写标记"一起清**（`_draft_dirty` / `_pending_sizes` /
  `_pending_boxes`）——`set_task` 开头会 flush 它们，只删文件不清标记等于
  "换完文件旧书的参数与检测框复活"。
- 步骤条（4 阶段）：当前步骤蓝色高亮、已完成淡蓝标记、点击切换。
- **记住上次停留的步骤**：每个任务各记一份（`ui.json` 的 `last_stage`），
  再次打开任务直接回到那一步；没有记录、或那一步在当前流程里不存在
  （如「图片拼版」节点因 area≠1 而不出现）时从第一步开始。记录写 key 不写
  下标，步骤增删后不会把人送到别的步骤去。
- **不自动跳回上次任务**（2026-10-06 改口径）：启动一律停在「任务管理」列表页，
  由用户点进哪个任务；点进去后仍落到那个任务上次停留的步骤（上面那条）。
  全局「上次任务」记录仍照写，留给将来的显式「回到上次任务」入口。
- 主体：左侧预览区（随阶段切换）+ 右侧控制列（限宽 340–440px）。
- 底部：执行日志**状态条**（常驻一行 34px：状态圆点 + 最近一条输出 + 清空/展开）。
  点击状态条从上方唤出**日志浮层**（盖住预览区下缘但不改变布局，实时滚动，stderr
  亦可见）；Esc、点击浮层外或再点状态条关闭。执行阶段时自动唤出，出错时圆点与
  摘要标红。

### 2.1 历史执行配置

- 控制列顶部下拉框：列出本阶段最近执行（时间 · 全量/续跑 · 状态）；
- 进入页面/切换阶段时自动回填最近一次参数；
- 选择历史条目一键回填表单（仅表单字段，不含 input/output 等运行时键）。

### 2.2 阶段预览

| 阶段 | 预览 |
| --- | --- |
| extract | [PDF 预览 \| 提取结果] 双标签；左侧条缩略图；结果条支持删页/插页 |
| detect | 图片 + 检测框叠加（绿/蓝实线）+ area 参考轮廓（橙虚线）；框可编辑 |
| rembg | 单视图：去底色结果优先，顶部「去底色结果/原图」切换；显示范围 = 检测框 + area/border |
| print | 左侧待打印缩略图条（拖动排序/删除/插入）+ 右侧**打印效果预览**（「打印效果/原图」切换）+ 参数表单（输出/边距/标题/页码） |

### 2.3 检测框编辑（detect 阶段）

- 点框选中（四角手柄），拖框内移动，拖手柄缩放，Delete 删除，空白拖拽手绘；
- 实时写库（origin=manual），手动结果不被自动结果覆盖；
- area=1 时条目按输出拆分（-r/-l，r 在 l 前），条目缩略图只显示所属框区域，
  标题为排序后序号 1,2,3…。

### 2.4 去底色预览（rembg 阶段）

- area=1：每框一条目（-r/-l），**左侧缩略图条每条只显示所属框的那半页**；
  area=2/3：每页一条目，显示整页；
- 缩略图的区域合成走 `_page_thumb_for()` 返回的 `effect`（含 `boxes`/`area`/`border`/`dpi`）
  交给 `ImageListWorker(effects=...)`，**不是 `crops`**（两者是不同入参，别拿错键）；
- 切换 area/编辑框/改 border 后区域实时重算；
- 右侧顶部的「去底色结果 / 原图」是一枚 `SegmentedToggle` 分段开关（灰底胶囊 +
  白滑块 + 主色加粗的选中文字），**不是两颗按钮**；还没有去底色结果时结果项置灰
  不可点、开关停在「原图」，但用户偏好不被改写——结果一生成就自动回到原来选的那一项；
- 提示文案标明当前显示的是结果还是原图及其范围。

### 2.5 生成 PDF（print 阶段）

- 左侧缩略图条：条目 = 去底色结果图片，与前几步同一枚 `ThumbStrip`
  （`set_reorderable(True)` 打开 InternalMove 拖动排序）；删除（按钮/Delete）、
  「插入图片」（引用外部文件路径）；列表持久化 print.json，首次进入由
  rembg 输出目录初始化。
- 右侧是**打印效果预览**，用「打印效果 / 原图」分段开关切换：
  - 「打印效果」按右侧参数把图片排进一张纸（白纸 + 图片 + 竖排标题/页码），
    **只是内存位图：不执行、不提交、不生成 PDF**；
  - 几何来自 `utils.page_layout.plan_print_page`，与 `functions/print.py`
    生成 PDF 用的是同一个函数（print.py 不再自己抄一份公式），所以预览与
    成品不会漂移；
  - 竖排里的拉丁段（`Happiness` 之类）由 `utils.page_layout.vertical_runs`
    切成"整段"，预览侧 `painter.rotate(90)` 画成竖条——与 fpdf 侧同一份分段；
  - 标题/页码的「距页边」也只在这里算一次：左页取「左」值、右页取「右」值；
    **图片不再为文字收窄让位**——填了距离就按距离画，允许压在图片上
    （表单只摆两行、每行一个通栏输入框：「左右边距：」（一个值管两边）、
    「上边距：」/「下边距：」；下面一行实时释义"文字轮廓距左右纸边各 …｜距上 …"）；
  - 参数填到一半（如颜色写成 `0,0`）时 `get_args()` 会抛错，预览捕获后
    退回「原图」并在说明行给出原因，不弹窗打断输入；
  - 命中「跳过页」的页画成灰色留白页并标注，明确告诉用户这页不会输出。
  - 预览参数**直接取自右侧表单**：详情页把 `PrintPanel.get_args()` 作为
    `params_provider` 交给预览控件，表单里任一影响版面的控件变化 →
    `params_changed` → 250ms 防抖后重画当前页（边距/颜色是逐字符输入，
    每敲一下都重载大图会明显卡顿）。
    ⚠️ 这个接线是**必须的**：漏传 `params_provider` 时预览永远停在
    「未接入打印参数，已显示原图」，标题/页码/纸张效果一概看不到，而组件
    自测（自己传参数）完全测不出来——由 `print_page_preview` 的集成级
    断言在详情页上兜住。
- 右侧参数表单：分「输出与纸张 / 页边距 / 标题排版 / 页码 / 过滤」五组，
  古籍名称与 PDF 文件名联动（填名称自动推导文件名）；
  「恢复默认配置」载入内置默认值、「放弃本次修改」回到最近一次执行参数。
  ⚠️ 「内置默认值」的**唯一来源**是 `panels/params_spec.py` 的 `DEFAULTS[stage]`：
  控件初值、`_apply_args` 的缺键兜底、`reset_to_default` 三处都从它取。
  面板里**不许再写** `p.get("键", 字面量)` 这种自带默认兜底的写法——
  `page_number_font_size` 就曾因此出现 12 / 18 两套值（详见 gui-architecture.md
  2.1 节与 `tests/selftests/params_spec.py` 的守卫）。

### 2.6 图片拼版（可选节点）

流程条节点框的语言（2026-09-30 定稿）：**真实步骤是实线 border 胶囊**，
「图片拼版」**默认虚线框**（选中后转实线主题色）——虚线 = 非真实流向，
与连接线同语言。节点框内**始终铺 SURFACE 实底**：连接线由流程条底层统一
画、**从节点框后面穿过**（框内那截被实底遮住），线看起来"从框后面出发"，
不用再对齐框边缘。拼版节点只在第三步「区域模式」**确定为 1** 时出现
（面板当前值/草稿/最近执行三者之一——全新任务没配置过去底色就不显示，
不凭内置默认冒出来），用户可选择也可不选择。节点有两条独立状态线：
**选择态**（「已选择/未选择」副标题 + 边框虚实/颜色）只管节点外观；
**生效态**（已启用且至少有一页拼版，``set_imposition_active``）决定连线
——未生效时它前后的连接线是**灰色虚线**，同时「图片去底色 → 生成 PDF」
在节点**上方画一条绕行线**：**横平竖直的直角折线**（向右 → 直角上 →
向右越过节点 → 直角下 → 向右，像铺管道；颜色规则同普通连接线：去底色
完成即绿），表达"真实流向此刻不经过拼版"；生效后绕行线消失、
两侧连接线恢复常规点亮。

- **左列**：拼版页清单「第一页 / 第二页 / …」，**每格左上有勾选框**——
  勾选多页后一条**悬浮操作条**（「已选 N 页」+「取消选择」「批量删除」）
  浮在清单下沿（勾选数归零自动收起）；「批量删除」**弹窗确认**后删页，
  语义与单页删除一致：版面调整丢失、图片释放回未选择列表。勾选**跨清单
  重建保留**（按副标题认页：拖动排序/加页不丢勾，页被删则自然落选）；
  勾选框的点击不会触发切页/排序。末尾一格是虚线的「＋ 选择拼版」，
  **钉在左列最底部**（页多页少都看得见）；
- **右区**：拼版操作画布（拖动 / 缩放拉伸 / 旋转），**纯白底、无纸张**，
  **点击某张图 → 选中**，选中的图带一圈**常显细虚线**；**按住操作期间**才
  升级为带四角四边手柄与上方旋转钮的完整虚线框，松手回到细框，切页/点空白
  取消选中；画面上有一条**恒显的
  红色垂直虚线**（`SPINE_COLOR`），落在左右两图 rect 中心的**中点**上——
  无论是否选中/拖动都在，整版旋转时是"转没转歪"的对比基准；另有一条
  **恒显的灰色虚线框**（`CROP_COLOR`）＝两图旋转后**外接框的并集**（上下左右
  最外侧点），与产出图的紧裁范围（`services.imposition.page_bounds`）同一套
  几何——框里有什么，成品就是什么；
- **右侧控制列**：状态行 + **两块分区**（用户 2026-09-30）——页级块
  **「操作当前图片页」**：**整体旋转**（度数框挂说明行右侧，滑块通栏独占
  一行按 **0.01°/格** 微调、输入框 2 位小数步进 0.1°，绕两图公共中心转，
  大角度直接键入）/ 复位本页版面 / 删除本页拼版（**这两个同行**）/ 清空全部拼版；
  图片级块 **「操作当前图片」**：旋转（绝对角度）——**只在画布里选中了某张图
  时激活并高亮**，未选中/切页后整块置灰；**「在流程中启用图片拼版」开关放
  面板最底部**。说明文字收在标题旁的**问号按钮**里（同其他步骤面板，
  `desktop.ui.widgets.HelpButton`）。「选择拼版」按钮不在面板上——入口只有
  左列末尾的虚线「＋ 选择拼版」格。翻页用**画布下方右侧**的
  「上一页 / 下一页」，页序在左列**拖动排序**——面板上没有上移/下移/
  左右转 90° 按钮（用户 2026-09-30 口径）；
- 该节点**没有可执行的子任务**：进入拼版详情时「执行本子任务 / 提交本次任务 /
  继续执行 / 中断执行」整组隐藏，执行记录与检测统计一并收起。

### 2.7 拼版与第四步的取图来源

第四步的图片来源由拼版是否**生效**决定（`ImpositionMixin.print_source_dir`）：

| 状态 | 第四步取图目录 | 是否再做区域合成 |
|---|---|---|
| 拼版生效（已启用 + 至少一页） | `stages/imposition`（已是成品整页） | 否，整页透传 |
| 否则 | `stages/rembg`（第三步提交产物） | 是（与旧行为一致） |

⚠️ 来源切换时，`print.json` 里属于**本任务别的阶段**的旧条目必须剔除，
否则会被当成"用户插入的外部图片"追加进 PDF（拼版 2 页 + 去底色 4 页 = 6 页）。
见 `services/print_plan.drop_foreign_stage_pages`。
