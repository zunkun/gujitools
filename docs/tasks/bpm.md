# bpm 驱动任务流程

任务流程采用 bpm 驱动，现在有如下任务节点

- 上传PDF
- 提取PDF图片
- 检测文本框
- 图片去底色
- 图片拼板
- 图片生成PDF

上面的几个步骤是目前已经存在的任务流程，现在需要改造成 bpm 驱动
因此，需要如下改造

## 改造模块

- desktop bpmn 节点绘制，包括自定义bpmn节点
- 后端bpm 驱动bpm 节点

## bpm 驱动bpmn文件

1. 按照现有流程，生成默认 task_default.bpmn 文件, bpm 驱动节点

## 任务节点改造

任务列表中 导入PDF 改成 “创建任务”，出现弹窗
弹窗如下

- 默认任务流程/自定义任务流程 checkbox 组件
- 默认任务流程下有选择PDF，上传 PDF 后自动进入任务详情界面
- 自定义任务流程下面有任务流程bpmn 节点渲染，默认是 task_detail.bpmn 的 节点渲染，同时提供按钮 “编辑流程” 点击调用 bpmn 自定义面板，编辑后同步到弹窗中，同时提供确认流程 按钮，进入详情页面
- **无论是否勾选「使用自定义任务流程」，弹窗里都要显示"当前流程长什么样"**
  （不勾 = 显示默认流程；勾上 = 显示自定义流程）。用户不该靠猜自己会跑哪条流程。

## 自定义bpmn 面板

自定义bpmn 面板 显示各种节点，可以多拽，线段连接，同时有 恢复默认 bpmn 流程选项
同时支持 bpmn 编辑操作

## 任务详情页面

按照bpmn 节点渲染节点，因为 任务详情目前各个节点已经解耦，因此可以按照bpmn 节点渲染，同时可以修改bpmn 节点

### ⚠️ 铁律：默认流程 = `task_default.bpmn`

> 默认流程必须跟 `task_default.bpmn` 一样，不一样的，改成一样，
> **不要你自己设计默认流程**。

具体含义，三条都要守：

1. **代码里不许再写第二份默认流程**。以前 `tools/gen_default_bpmn.py` 会从
   `ports.SUPPLIERS`（端口级依赖边表）**派生**出一份写进模板文件，那是"代码
   设计默认流程"，已删除。该工具现在只做**校验**（`python tools/gen_default_bpmn.py --check`）。
2. **界面上的文案不许手写步骤串**。创建任务弹窗的默认提示改成
   `default_hint(图)`：前缀 + `summarize(图)`，步骤串**从文件读**。
   以前那里写死了"提取图片 → 检测文本框 → 图片去底色 → PDF排版"，与文件
   实际内容各说各话。
3. **本文件里凡是描述默认流程的地方，一律以上面那个文件为准**。下面这一节
   就是照文件抄的，改文件就要改这里。

### 默认流程现在长这样（照 `task_default.bpmn` 抄，2026-10-05 18:32 版）

```
┌────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐       ┌──────────┐
│ 源PDF  │→ │ 提取图片 │→ │检测文本框│→ │图片去底色│→ │ 是否拼版 │──否──→│ PDF排版  │→ 生成PDF
└────────┘  └──────────┘  └──────────┘  └──────────┘  │  (网关)  │       └──────────┘
                                                        └──────────┘             ↑
                                                             │是          ┌──────────┐
                                                             └──────────→│ 图片拼板 │
                                                                          └──────────┘
```

- 节点（8 个）：`源PDF`(startEvent) / `提取图片` / `检测文本框` / `图片去底色` /
  `是否拼版`(exclusiveGateway) / `PDF排版` / `图片拼板` / `生成PDF`(endEvent)。
- 连线（8 条）：`源PDF→提取图片→检测文本框→图片去底色→是否拼版`；
  `是否拼版 --否--> PDF排版`（默认路径）；`是否拼版 --是--> 图片拼板`；
  `图片拼板→PDF排版`；`PDF排版→生成PDF`。
- 运行步骤（状态机的输入）：`extract → detect → rembg → imposition → print`。
  `imposition`（图片拼板）是**可选**步骤，未启用拼版时被状态机跳过。
- 界面槽位：`提取图片(格0/页0) / 检测文本框(格1/页1) / 图片去底色(格2/页2) /
  图片拼板(格3/页4,可选) / PDF排版(格4/页3)`。

> `rembg_submit`（提交去底色结果）**不再单独成节点**：它是第三步内的第二个动作，
> 在界面槽位里折回「图片去底色」那一格。

### 曾经错在哪（别改回去）

`task_default.bpmn` 原来的 8 条连线**每条都带 `guji:port`**：

```
extract --pages--> rembg            extract --pages--> imposition
extract --pages--> rembg_submit     detect  --boxes--> rembg
```

这些是**端口级"去谁那儿取产物"的依赖**（`rembg.pages ← extract`），被
"生成默认流程"的代码原样写成了 `sequenceFlow`。它作为*依赖图*是对的，作为
*流程图*是错的——画出来是从「提取图片」炸出去的一团，路径还会跳过步骤。
判定依据：**流程连线表达"先后"，端口依赖表达"取谁的文件"，两者不能互转。**

### 源 PDF ↔ 提取图片：成对存在（2026-10-06）

用户口径：

> 流程编辑中，如果删除了 上传pdf 或者 pdf图片提取中的一个，另外一个的存在
> 没有意义，因此需要同步删除另外一个。

`extract` 是**唯一**吃源 PDF 的步骤，而「源 PDF」在图上是那个 `startEvent`
（**没有 `stage`**，它的语义标记是 `ports.SUPPLY_TASK_SOURCE`）。所以这一对
必须**成对存在**：

- 只删 `extract`、留着源 PDF ⇒ 图上有个入口却不产出图片，第一步照样跑不动；
- 只删源 PDF、留着 `extract` ⇒ 它吃的是任务源 PDF，而界面上那个 PDF 图标
  会**仍然亮着**催你上传——正是"不需要 PDF 上传图标"那类流程的由来。

配对判据是**图上的性质**，唯一实现 `ports.paired_node_for_stage(diagram,
node_id)`（认源 PDF 走 `source_pdf_node_ids()`：事件类型**或**节点名），
⚠️**别在编辑器里写死 `"extract" ↔ "startEvent"`**——那是对图模型的声明。

**删除有两条路径，两条都要成对**：工具栏「删除」（`ask_delete_selected`）
与键盘 Delete（`remove_selected`）。只改一处，键盘删就会漏。

顺带：页头那个 PDF 图标的**显隐**现在看 `ports.flow_needs_source_pdf()`——
流程压根不吃 PDF 时整颗藏起来（摆在那儿是噪声，还会让人以为这步要 PDF）。
⚠️**只在"流程不碰 PDF"时藏**，空壳任务（还没选 PDF 但流程要）必须**恒显示**，
否则用户就再也没法自己补了。

### 入口节点：没有上游也要有输入（2026-10-06）

自定义流程可以把**任何一步**放在第一位。用户口径：

> 如果某个节点作为第一个节点，一定要可以有输入可用。

此前"图片输入"只有一条来路＝上游的 `pages` 端口，于是把「检测文本框」放在
第一位时会连着出三处故障：

| 现象 | 根因 |
| --- | --- |
| 点执行弹「输入未接好」 | 沿图回溯不到供给方 → `stage_input` 返回 `None` |
| 预览永远「暂无图片，请先完成提取」 | 页面清单只有 extract 跑成功才刷新 |
| 左下角插了图，左侧列表不显示 | ① 插图只往 `stages/extract/` 写；② `_refresh_preview()` 拿**栈页号**当**格序**用（此流程里 detect 是格 0 / 页 1）|

现在的规则（**唯一实现**在 `ports.resolve_input_with_entry`）：

1. 某阶段某端口**沿图回溯不出上游**，且该阶段确实吃 `pages` ⇒ 回落到
   **入口图片目录 `tasks/<id>/stages/input/`**（落点由
   `ports.TASK_INPUT_LOCATION` 唯一声明）；
2. `boxes` / `pdf` **不许**回落——用户不会手写 `boxes.json`，让它们回落等于
   把"接口没接好"伪装成"有输入了"，比报错更难查；
3. 有上游时行为**一字不变**（默认流程照旧走 `stages/extract/`）；
4. 插图目标目录与执行读目录**必须同源**（都走 `store.stage_input`），
   否则会出现"插进去了却读不到"。

⚠️ 这条回落**只解决"没有上游"**，不解决"上游还没跑"：那属于状态机的
`missing_stages`，两件事别混。

### ⚠️⚠️ 铁律之二：**图必须压过静态连线表**（2026-10-06 掉头）

> `ports.SUPPLIERS` 是**一份写死在代码里的默认流程连线**。它只能当**兜底**，
> 绝不能压过用户在 `flow.bpmn` 里画的线。

原规则是**反的**（"先静态声明、后沿图回退"），后果是：只要静态表给的供给方
**还留在流程里**，用户画的所有连线一律作废。可复现的证明——两条**节点集合完全
相同、连线不同**的流程：

| 流程 | 连线 | `print` 取图目录（旧） | （新） |
| --- | --- | --- | --- |
| A 默认 | `extract→detect→rembg→print` | `stages/rembg` | `stages/rembg` |
| B 用户改的 | `extract→print`（明确跳过检测/去底色）+ `rembg` 仍在流程里 | `stages/rembg` ❌ | `stages/extract` ✅ |

这就是"自定义流程里总是冒出默认流程逻辑"的**病根**：**BPM 化只覆盖了"顺序"，
没覆盖"语义"**——用户能决定跑哪几步，却决定不了数据从哪来。

现在的规则（`store.stage_supplier`）：

1. **不声明的端口 ⇒ 没有这个输入**（`ports.stage_inputs` 是唯一真源；这条必须
   在查图**之前**，否则 `print` 会沿图撞上 `detect` 而拿到 `boxes.json`）；
2. **图能给出唯一答案 ⇒ 图说了算**（`FlowDiagram.producers_of` 恰好一个产出方）；
3. **图说不清 ⇒ 退回静态声明 + 条件开关**。

⚠️ 第 3 条是**确定性**的要求，不是将就：默认流程带「是否拼版」网关，两条
**实线**都通向「PDF排版」，沿图回溯会同时看到「图片拼板」与「图片去底色」——
那种情况必须靠 `ports.print_pages_supplier(imposition_active)` 这个**运行态**
来选，靠遍历顺序选是随机的。

⚠️ `producers_of` **遇到产出方就停**，不继续往它上游穿：线性链里 `print` 的产出
方是 `rembg` 而**不是** `extract`（后者只是 rembg 的上游）。若按"可达"判，线性链
也会被误判成"多个产出方"而退回静态表，等于图白做。

自测 = `step_ports` 第 9d 节（含**双向验证**：还原成静态优先即红）。

### ⚠️ 铁律之三：**改名不断绑**——阶段身份是节点的属性，不是名字算出来的

以前阶段是改名时**重算**的（按名字查 `STAGE_ALIASES`）：把「图片去底色」改名成
「AI 抠图」⇒ 认不出任何阶段 ⇒ 不产出任何端口 ⇒ 整张图 `stage_order()` 为空 ⇒
被判"坏图" ⇒ **静默回落默认流程**。用户只是改了个标签，流程却被换掉了——
"默认流程突然出现"的机制性原因其实是**身份只活在名字里，落盘时还不保存**。

现在的规则（`BpmnEditor.rename_node` + `FlowDiagram.to_xml`/`load`）：

- 阶段身份落盘在 **`guji:stage`**（`load` 本来就会优先读它，只是以前 `to_xml`
  从来不写——自己编辑器存的图重读也只能靠名字猜）；
- 新名字能认出阶段 ⇒ 换绑到那个阶段（"改名切换步骤类型"，有意保留）；
- 新名字认不出 ⇒ **保留原阶段**，只改显示（手滑改名不再炸掉整张流程）；
- 本来就没阶段的节点 ⇒ 改名不许凭空接上（随手一改多出运行步骤更糟）。

要解绑（留着节点但不跑）请删节点——改名不提供这条路。外部工具（bpmn.io）
可能丢弃它不认识的 `guji:stage` 属性，丢了就退回名字匹配＋降级告警（那条路
照旧，由 `store.flow_degraded_reason` 兜底）。

自测 = `flow_ui`（保留原阶段 / 已知改名换绑 / 不凭空接上 / 存盘重读带身份，四条）。

### ⚠️ 铁律之四：条件开关从 spec 派生，`SUPPLIERS` 只兜底、不优先

两条容易写成"默认流程写死"的线，口径如下：

- **跳过规则**（状态机）：`scheduler.CONDITIONS` 从 `SPECS` 的
  `role == "optional"` 派生（`{步骤: 步骤}`），不是手写表。开关状态走通用的
  `store.step_enabled`（`drafts/<步骤>.json` 的 `enabled`）+ `store.scheduler_flags`
  一次建成——再加一个可选步骤，条件表、flags 键自动跟着走，调用方不用改。
  唯一的调用方特例是 `imposition` 那一键用传入值覆盖：调用方传的是
  `imposition_effective()`（在流程里 ＋ `area == 1` ＋ 开关三道闸），而纯开关
  读数在区域模式不支持时会把下游指去一个空目录。
- **取图目录**（`store.stage_supplier`）：铁律之二的三条规则——端口声明守门、
  图唯一则图说了算、图说不清才退回 `SUPPLIERS` ＋条件开关。

自测 = `step_ports` 第 9e 节（派生相等 / 开关同源 / flags 键集合 / 通用跳过）。

## 架构：`flow.bpmn` 是唯一真源

```
                    ┌── 渲染/编辑 ──> desktop/components/bpmn_view.py   (只读)
flow.bpmn ──读──> FlowDiagram        bpmn_editor.py + bpmn_editor_panel.py (编辑)
（唯一真源）     (节点类型+坐标+折点)  │
                    └── 运行顺序 ──> desktop/steps/scheduler.py (状态机)
```

| 模块 | 职责 |
| --- | --- |
| `desktop/steps/bpmn_diagram.py` | **忠实模型**：读/写整张图（任意节点类型 + DI 坐标 + 折点 + 边标签） |
| `desktop/components/bpmn_view.py` | 照文件渲染：网关画菱形、结束事件画双圈、连线走文件折点 |
| `desktop/components/bpmn_editor.py` | 画布交互：拖拽 / 拖**中线连接点**连线（上下左右四向自动匹配）/ 点到点连线模式 / 自动排版 / 选中（节点与连线）/ 双击改名 |
| `desktop/components/bpmn_editor_panel.py` | **工具栏** + **固定节点面板** + 可滚动画布 + 选中状态行（"能编辑"靠它，画布本身没有按钮） |
| `desktop/components/bpmn_palette.py` | **固定节点面板**：拖一个到画布就加一格；已在流程里的**置灰**，删掉后恢复可拖 |
| `desktop/components/flow_dialog.py` | 查看/编辑弹窗（详情页与创建任务弹窗共用），打开即编辑态 |
| `desktop/steps/scheduler.py` | **状态机**：有序阶段 + 跳过规则（替代端口级边表推顺序） |

### 为什么不用现成的 BPMN 渲染引擎

查证过，**能直接用的没有**：

| 候选 | 结论 |
| --- | --- |
| bpmn-js（bpmn.io 官方，画图就是从它导出的） | JS 库，必须浏览器 / QtWebEngine（+196MB Chromium，已排除） |
| pm4py | 渲染**依赖 Graphviz 外部二进制**，只能导出 PNG，嵌不进 Qt 控件 |
| bpmn-python | 同上，走 Graphviz |
| processpiper | 「文本语法生成图」，渲染不了任意 bpmn 文件 |

所以扩展现有自绘渲染器（`QPainter`）是唯一可行路线。

### 后端为什么用状态机

旧的 `FlowDefinition` 把流程表达成端口级依赖图，回答"这一步去谁那儿取产物"，
能表达任意拓扑，但推"下一步该跑谁"要走一堆图算法。用户明确说这太重。

新 `Scheduler` 只做三件事：

- **顺序** —— 取 BPMN 图的**拓扑序**（`stage_order()`）；
- **跳过** —— 这一步在不在图里、条件是否满足；
- **分支** —— 一张极小的条件表 `CONDITIONS`，不引表达式引擎。

产物路径仍走 `ports` 的落点表（那是"文件放哪儿"，与"谁先谁后"无关）。

⚠️ **拓扑序不能退化成遍历序**：图上从分支点分开的两条路，广度遍历会先撞到
"短路"那条，把下游阶段排到前面。Kahn 算法保证所有前驱排完才轮到它。

### 「是否拼版」：三个判据，各管一件事

用户口径（2026-10-05）：**拼版的操作放在拼版面板里，它可以用，但是否生效
由…**。逐层查证业务流程后（`area` 的真实语义 + `-l/-r` 半页后缀**只在
`area=1` 产生** + 拼版是 `ITEMS_PER_PAGE=2` 两张并排），定成三态：

| 判据 | 由谁决定 | 答的是什么问题 |
| --- | --- | --- |
| ① **在不在流程里** | **流程图**（`bar_index_of_step("imposition")`） | 这一步存不存在 |
| ② **有没有意义** | 第三步「区域模式」`area == 1` | 这步在当前参数下该不该跑 |
| ③ **要不要真跑** | 拼版面板底部开关（`imposition_active`，只看勾没勾＝**用户意图**） | 用户打不打算用 |

三者全过才算 `imposition_effective()`＝**能不能真跑**。取图来源、状态机跳过、
步骤条生效态**一律认 effective**；只有"文案里说没说勾"认 active。

**为什么 ② 不能省**（本轮一度误判删掉，又按业务流程查回来）：

- `area=1`「左右分开」：每个文本框产出**成对的两张**半页图（`-l` / `-r`），
  两张并排才拼得出**正刊对开版面**——这才是拼版存在的意义；
- `area=2/3`：两框取并集输出**一张整图**；`area=4`：整页一张 ⇒
  本来就是一张图，再拼没意义（那是"把两页装订在一起"，不是版式）。

所以 `area` 不是"显示开关"，而是**适用前提**。旧实现拿它当显示条件
（`area≠1` 就不显示节点），用户报过"改了 area 节点凭空消失"；现在改成
**置灰 + 说明原因**，节点照旧显示——用户看得见"流程里有这一步但当前用不上"。

⚠️ **处置是置灰不是取消勾选**：勾选是用户的**意图记录**，取消它会静默丢掉
"我打算用"的信息；改回 `area=1` 就自动恢复生效。`_sync_imposition_switch`
也要**回填勾选态**（盘上才是准的，可能被历史恢复等别的入口改过）。

⚠️ **"勾了但用不上"要有中间档文案**：只说"已启用"与实际取图矛盾，只说
"未启用"又让用户怀疑"我明明勾了"。所以状态行 / toast 在
`active and not effective` 时说"已勾选但当前用不上：<原因>"。

用户能在 bpmn.io 里随手加一个「OCR 识别」。它**没有**对应实现，所以：

## 实测踩到的坑（都已加自测钉子）

1. ⚠️ **端口依赖 ≠ 流程连线**。见上文"曾经错在哪"——把
   `(consumer, port) → supplier` 边表写成 `sequenceFlow`，默认流程图就成了一团。
1b. ⚠️⚠️ **栈页号 `stack_index` 必须"查静态表"，不能"数当前有几格"**
   （2026-10-05 实测踩中，用户报"改了 task_default.bpmn 程序没跟着变"）：
   两个栈（`control_stack` / `preview_stack`）是**按静态步骤表一次建好固定页数**
   的（`FLOW_STAGES` 各一页 + `OPTIONAL_STEPS` 追加在末尾），**与流程图文件
   无关**。若 `stack_index` 按"本图里实际有几步"顺序编号，文件里**少一步**
   （例如默认流程不含「图片去底色」）时后面每一步的页号都**整体前移**——
   点「PDF排版」会翻到「图片去底色」那一页。正确做法是查
   `FlowDiagram.stage_slots()` 里的静态位置表。
2. ⚠️ **`endEvent` 会被名字误认成运行阶段**。结束事件常叫「生成 PDF」，
   按名字查别名表会认成 `print`，状态机多跑一遍、顺序全乱。
   现在**只有 `task` 才映射运行阶段**。
3. ⚠️ **`BpmnEditor` 只有画布、没有按钮**：`ask_add_node` / `ask_rename_selected`
   / `ask_delete_selected` 三个动作写好了，**从没有任何调用点**——用户看到的是
   "能选中有反应，但改不动"。修法是把动作摆成工具栏（`bpmn_editor_panel.py`），
   并让自测**点按钮**验证接线（不是直接调函数）。
4. ⚠️ **节点与连线的选中必须互斥**。不互斥会出现"两个东西都高亮"，而「删除」
   只能删一个——按下去删错了才发现。`BpmnEditor.set_selected*` 里互相清。
5. ⚠️ **自定义初值文件缺失会静默退化成默认流程**：`load_custom_init()` 找不到
   `task_detail.bpmn` 就回落默认图，于是勾不勾「自定义」看到的图**一模一样**
   （用户报的正是这个现象）。现在面板会**明确告警**，自测也钉了"两张图必须不同"。
6. ⚠️ **编辑器画布要有尺寸下限**（跟随视口）。只按内容给大小，图很小时控件只有
   一小条，节点拖不到旁边去（鼠标一出控件就从滚动区走了）。
7. ⚠️ **qfluentwidgets 的 `Dialog` 放不下成套面板**：签名是
   `Dialog(title, content: str, parent)`——第二参是**字符串** content，
   **没有** `viewLayout()` / `cancelButton`。三个弹窗同时踩中，而**自测全都直接
   实例化 `*Panel`、从不构造外壳**，所以"点开就炸"一直没被发现。现统一走
   `desktop/components/dialog_shell.py::shell_dialog`。
   **教训：凡"点按钮就炸、但自测全绿"，先怀疑外壳。**
8. ⚠️ 面板的 `self.close()` 关不掉弹窗（面板自己没窗口）——要点 `self.window()`。
9. ⚠️ `qfluentwidgets.PushButton` 的 `clicked` 发的是**无参**信号；按
   `def _on_x(self, checked: bool)` 接会 TypeError。用缺省参数兜。
10. ⚠️ PySide6 **不导出** `QWIDGETSIZE_MAX`；要"不限宽"用 `(1<<24)-1`。
11. ⚠⚠️ **`area` 是拼版的适用前提，不是"显示开关"**（本轮一度误删又查回）。
   只有 `area==1` 才产出成对 `-l/-r` 半页图，拼起来才是正刊对开版面；
   2/3/4 本来就是一张整图。⚠️ 处置是**置灰 + 说明**不是隐藏（隐藏会让用户
   以为节点凭空消失）。
12. ⚠⚠️ **界面与执行必须同一个判据**。只把 UI（预览的取图目录）改新判据、
   而 `runner`/`print_list` 仍认旧的"勾没勾"，会得到**界面说 A、执行做 B**
   ——比不改更坏。改法：全部认 `imposition_effective()`；`imposition_active()`
   只留给"文案里说没说勾"。
13. ⚠️ **`stage_states` 的键不能删，只能加标记**。调用方大量硬索引
   （`stage_states(tid)["rembg"]["status"]`），把不在流程里的阶段从字典里删掉
   会 KeyError，症状是"点了没反应"的崩溃而不是干净降级。现在**保留四个静态键**
   + 另加 `in_flow` 标记。
14. ⚠️ **沿图回退取产物时要"折叠到同格最靠后的动作"**
   （`bpmn_diagram.fold_forward`）：图上只有「图片去底色」，而真正产出成品的是
   同格的「提交去底色结果」（`rembg_submit`）。直接取 `rembg` 会拿到**实时预览
   目录** `stages/rembgpreview` 而不是用户提交过的 `stages/rembg`——
   **打印出来是没提交的图**（比报错更难发现）。
15. ⚠️ **自测里别用 `rows[0]` 找任务**（列表页断言）：模块中途新建的临时任务
   会排在更前面、把那一行抢走。曾因此让"启用拼版：列表多一个子任务"假红。
   临时任务用完要 `delete_task` 删掉。
16. ⚠️⚠️ **左侧列表缩略图的"逐张到齐"回填不许整列重灌**（用户 2026-10-06 报
   "拼板阶段程序卡死"）。旧实现每收一张缩略图就 ①重读整份
   `drafts/imposition.json`（380 页 = 97KB × 7.4ms）②对**全部**条目重跑
   `set_thumb`（每次都重跑 `scaled(SmoothTransformation)`，且无早退）——
   380 × 380 ≈ **7.2 万次**，主线程连续占住 **27.5 秒**，事件循环一次都转不到。
   现在只贴刚到的那一条（`ImpositionViewWidget.set_thumb_at`），定位走
   `_imposition_rep_index` 缓存（不再重算 reps、不再读盘）。实测 **0.06 秒**。
   同族：`ImpositionPageList.set_thumb` 还加了"同一张图早退"（判据用
   `QPixmap.cacheKey()`）。自测 = `imposition` 第 6 节（钉**调用形状**：
   `set_thumb` 次数 ≤ 条目数、`load_imposition_doc` 回填期间 0 次调用）。
